2026-06-30 结论：projection-aware、多视图几何条件、q_splice 加噪与 pure-noise 问题

1. 从 0.90 进入 1.0 pure-noise，projection-aware 不能单独解决。

projection-aware / geometry-aware multiview condition 的作用是让模型更清楚：

  哪些 latent voxel / sparse coords 在哪些 view 中可见；
  哪些区域被 mask / point prior 支持；
  多视图图像特征和 canonical 3D 空间如何对应。

这会改善条件信息质量，但它不是 pure-noise rollout 的充分条件。t=1 附近 unknown region 基本是随机噪声；如果 sparse inpainting flow 本身没有学会从随机噪声 + 条件一步步积分回目标 latent，投影条件再好也只能给方向信息，不能自动修正一个没有训练好的高噪声 vector field。

所以 projection-aware 可以帮助 high-t，但前提是训练也覆盖 high-t / pure-noise 分布，并且训练的是能改变 denoising vector field 的模块。

2. 当前 q_splice 加噪不是 Point-to-3D 正式推理思路。

严格区分三件事：

  q_splice = m_s * q_vis + (1 - m_s) * q_gt

这是 oracle 上限，因为 unknown 区域用了 q_gt。真实推理时没有 q_gt。

  q_splice_noise = q_splice + small_noise

这是 off-schedule oracle diagnostic。它用接近 clean 的 q_splice 加一点噪声，不等价于 flow schedule 中某个真实 t 的状态。它可以测试“如果起点已经很接近正确答案，采样会不会被模型破坏”，但它不是论文正式方法。

  q_splice_t = x_t(q_splice, t)

这个更接近合理诊断。它用 TRELLIS sampler 的 forward noising / xstart_to_xt 把 q_splice 放到指定 t 的轨迹上。它回答的是：如果初始状态位于正确 trajectory 附近，模型能不能从 t=0.75 / 0.90 走回去。

Point-to-3D 的正式推理不是 q_splice 加噪。正式推理是：

  known region: 每一步 hard clamp 到 q_vis
  unknown region: 从 noise 开始
  model input: concat(m_s*q_vis + (1-m_s)*q_t, m_s)
  model output: 预测 flow / velocity，把 unknown region 从噪声生成到目标结构

3. 为什么原论文理论上能解决 pure-noise？

关键不是 q_splice，也不是 projection-aware 本身，而是 G_inp 的训练分布。

原论文路线的核心是训练一个 sparse-structure inpainting flow G_inp，让它在训练时反复看到：

  q_t 来自 q_gt 在任意 t 的 noising；
  known region 被 q_vis 替换；
  mask m_s 告诉模型哪些是 observed，哪些要补全；
  condition 提供图像 / 点云先验；
  target 是完整 q_gt 的 denoising / flow target。

也就是说，模型在训练时就被教会：

  当 unknown region 在高 t 接近随机噪声时，
  如何利用 q_vis、m_s、图像条件和点云先验，
  一步步生成完整 sparse latent。

论文不是绕开 pure-noise，而是把 pure-noise 到 complete latent 这个任务作为 G_inp 的正式训练目标之一。

4. 为什么我们当前代码还不行？

当前失败的核心不是“没有 projection-aware”一个问题，而是多个限制叠加：

  1. phase1 主要训练 t <= 0.75，天然没有学 t=1 pure-noise；
  2. phase2 直接扩到 [0,1] 后，高 t 有改善有限，同时会损伤 low/mid-t 稳定性；
  3. view-gated / geometry adapter-only 只训练 condition adapter，不能充分修改 sparse flow 的 high-t vector field；
  4. input-layer-only / adapter-only 都是保守训练，不等价于论文的 full G_inp fine-tune；
  5. pure-noise rollout 是长链积分问题，teacher-forced / q_splice_t 好，不代表从随机噪声出发也能保持在正确轨迹；
  6. 当前 image condition、多视图融合、pose/point projection 还没有达到论文理想条件；
  7. 数据量和训练步数也明显小于一个真正的生成式 inpainting flow 训练。

所以当前结果可以理解为：

  q_vis / m_s / q_splice 数据链路是有效的；
  low/mid-t inpainting 有一定能力；
  但 pure-noise entry 的 G_inp 还没有学会。

5. projection-aware 后续是否仍然值得做？

值得做，但不要期待它单独解决 pure-noise。

更准确的路线应该是：

  A. projection-aware / geometry-aware condition：
     解决多视图图像、相机位姿、点云先验如何对齐到 canonical 3D latent 的问题。

  B. high-t / pure-noise G_inp training：
     解决 unknown region 从随机噪声生成完整 sparse latent 的问题。

这两个是互补关系：

  projection-aware 提供更强条件；
  G_inp high-t 训练提供从噪声生成的能力。

只有 A 没有 B，模型知道“应该看哪里”，但不会从噪声走回正确形状。
只有 B 没有 A，模型能生成，但未必能正确利用 AR 点云和多视图 pose。

6. 当前最清楚的判断

  q_splice_noise：只是 oracle / stress diagnostic，不是正式论文推理。
  q_splice_t：是更干净的 trajectory diagnostic。
  projection-aware：合理且必要，但不能单独跨过 0.90 -> 1.0 pure-noise gap。
  Point-to-3D 解决 pure-noise 的根本方式：训练 G_inp 在 full time range 上从 q_comb(t), m_s, condition 预测完整 q_gt 的 flow，而不是靠 q_splice 初始化。

7. 后续建议

短期：

  继续跑 geometry_view_gated s500，确认多视图几何条件是否比 view_gated s500 有收益。

中期：

  如果 geometry s500 有收益，再进入 projection-aware adapter；
  同时准备更接近论文的 G_inp 训练：不只 adapter-only，而是至少训练新增输入层 + 部分 flow / LoRA，并覆盖 high-t。

长期：

  真正要复现论文 pure-noise 能力，需要 full G_inp fine-tune 或足够容量的 LoRA/adapter fine-tune，
  且训练分布必须包含 t 接近 1 的 q_comb(t)。


2026-06-30 继续结论：为什么当前没做到原论文的 G_inp 训练分布，原论文怎么训练 high-t / pure-noise，我们能不能复现

1. 我们不是“不能”做 G_inp 的训练分布，而是当前还没有真正做到。

当前代码已经实现了论文形式的核心输入：

  q_comb(t) = m_s * q_vis + (1 - m_s) * q_t
  x_inp = concat(q_comb(t), m_s)

但当前训练和原论文仍有关键差距：

  1. 训练范围：
     我们的 phase1 主训练是 t in [0, 0.75]，没有覆盖 t 接近 1 的 pure-noise 端。

  2. 训练对象：
     我们为了稳定做过 input-layer-only / adapter-only / view-gated adapter-only。
     这些不是原论文的 full G_inp fine-tune。

  3. 训练规模：
     我们目前主要是 train64 / train512 / val128 级别，
     原论文是更大数据、更长训练。

  4. 条件路径：
     我们的多视图 / geometry-aware condition 还只是初版；
     原论文的训练样本是严格由可见点云和完整 GT structure 对齐构建。

  5. 采样稳定性：
     teacher-forced 或 q_splice_t 好，只说明局部轨迹附近可用；
     从 t=1 随机噪声长链积分仍需要模型真正学过 high-t vector field。

所以准确说：

  我们可以构建 G_inp 训练分布；
  当前只是还没有用足够容量、足够 high-t、足够数据规模去训练它。

2. 原论文 high-t / pure-noise 是怎么处理的？

原论文不是靠 q_splice 加噪解决 pure-noise。

它的做法是：

  A. 先把 visible point cloud voxelize；
  B. 用 TRELLIS sparse structure VAE encoder 得到 q_vis；
  C. 从 visible occupancy 下采样得到 mask m_s；
  D. unknown region 用 noise / q_t 表示；
  E. 输入 concat(m_s*q_vis + (1-m_s)*q_t, m_s)；
  F. 用完整 GT sparse latent q_gt 作为监督；
  G. full fine-tune structure inpainting flow transformer G_inp；
  H. inference 时每一步重新拼 q_vis / mask，并分 structural inpainting + boundary refinement 两阶段采样。

换句话说，原论文能处理 high-t / pure-noise 的核心原因是：

  训练时就让 G_inp 在完整时间分布上见过 unknown region 从噪声状态恢复到 q_gt 的任务。

不是因为推理时用了 q_splice。

3. 原论文为什么“就可以”？

从论文描述看，关键条件有四个：

  1. full fine-tune G_inp：
     它不是只训练新增 input layer，也不是只训练 condition adapter。
     它替换输入层后，保持其他结构继承 TRELLIS，然后 full fine-tune inpainting flow。

  2. task-specific visible-complete training pairs：
     每个训练样本都有：
       visible point cloud prior
       q_vis
       m_s
       complete q_gt
     这正好对应 inpainting 任务。

  3. full CFM time distribution：
     CFM 训练天然随机采样 t。
     只要 t 覆盖到接近 1，模型就会学 high-noise / pure-noise 状态下的 vector field。

  4. 训练规模足够：
     论文实现细节写的是 20k iterations，batch size 8，4x A100。
     这比我们现在的 adapter-only s20/s500、phase1/phase2 小得多。

因此论文的 pure-noise 能力来自“完整训练分布 + 足够容量 + 足够训练规模”，不是某个推理 trick。

4. 我们当前为什么不行？

当前最直接原因：

  1. phase1 根本没有训练 t > 0.75；
  2. phase2 直接拉到 [0,1] 后，high-t 有提升但会损伤 low/mid-t，说明训练还不稳；
  3. adapter-only 训练不会改变 sparse flow 的 denoising vector field；
  4. input-layer-only 容量太小；
  5. full-flow 小数据训练容易破坏 TRELLIS base prior；
  6. 当前数据量和训练步数还不足以学会 t=1 rollout。

所以我们目前看到：

  q_splice_t 0.75 可以；
  q_splice_t 0.90 变差；
  noise_t1 / pure-noise 仍差。

这是符合预期的。

5. 我们能不能复现？

可以复现“方向”，但要分层。

第一层：当前代码已经基本具备的部分

  q_vis / q_gt / m_s latent dataset；
  q_comb(t) 输入；
  mask channel；
  CFM loss；
  staged sampling；
  q_splice_t / noise_t1 eval。

第二层：还需要补足的部分

  1. 更大的 latent manifest：
     train1488 甚至更大，而不是只 train512。

  2. 更接近论文的 full G_inp fine-tune：
     至少不是 adapter-only。
     可以先用 LoRA / partial flow 解冻作为安全折中，
     但严格论文是 full fine-tune。

  3. high-t curriculum：
     不能只训 [0,0.75]；
     需要平滑过渡到 [0,1]，并避免破坏 low/mid-t。

  4. 训练资源：
     论文是 20k iters、batch 8、4 A100。
     我们单卡 24GB 只能做 batch 1 / 小步数，训练效果不能直接对标。

  5. 数据构造严格性：
     原论文用 rendered depth + camera pose 得到真实 visible point cloud；
     我们当前 q_vis 是 point prior dataset 生成的 AR-like / multi-view visible prior，
     可以用，但要确认它和 condition image/view 完全对齐。

6. 对我们最现实的复现路线

不建议直接从现在的 adapter-only 跳到 full-flow [0,1] 长训。

建议：

  Step 1:
    跑 geometry_view_gated s500，确认更强 condition 是否比 view_gated 有收益。

  Step 2:
    开一个 partial G_inp fine-tune：
      train input layer
      train 前几层/后几层 transformer block 或 LoRA
      freeze 大部分 TRELLIS base
    时间范围先 [0,0.85]，再 [0,0.95]，最后 [0,1]。

  Step 3:
    如果 partial fine-tune 在 q_splice_t0.90 和 noise_t1 上明显改善，
    再考虑 full G_inp fine-tune。

  Step 4:
    扩大到 train1488 / 更大 synthetic dataset。

7. 最关键的一句话

原论文能解决 pure-noise，不是因为 q_splice，也不是因为 projection-aware 本身；
而是因为它把 “known region = q_vis，unknown region = noisy q_t，target = q_gt” 作为正式训练分布，
并 full fine-tune G_inp 足够久。

2. projection-aware 结构是什么？

当前实现不是完整的 voxel-to-image-token projection transformer，
而是一个 latent-grid visual support adapter。

原 strict Points-to-3D 输入仍然是：

  q_comb = m_s * q_vis + (1 - m_s) * q_t
  flow input = concat(q_comb, m_s)

也就是 sparse flow 的输入层从原 TRELLIS latent channels 扩成：

  latent + mask

多视图图像仍然先走 TRELLIS image encoder：

  images -> cond_views [B, V, T, C]

新增的是 projection feature。

对每个 16^3 latent cell center：

  latent cell center
  -> grid_transform，例如 pixal3d_rotation
  -> 用每个 view 的 intrinsic / extrinsic 投影到原始 mask
  -> 统计是否 visible / 是否落在 mask 内

输出三通道：

  visible_ratio
  support_ratio_over_views
  support_over_visible

shape：

  [B, 3, 16, 16, 16]

adapter 的 geometry 输入从原来的：

  q_vis 8 channels + m_s 1 channel = 9 channels

变成：

  q_vis 8 + m_s 1 + projection_features 3 = 12 channels

然后用 3D conv 做 geometry summary，
再调制多视图 image tokens 的 view gating / FiLM。


3. 这一阶段主要测试什么？

它测试的是：

  当前 high-t 失败是否因为 condition 仍太全局，
  没有告诉模型每个 3D latent cell 在哪些视角可见、
  是否被 mask 支持。

换句话说，它不是直接证明 pure-noise 已经解决，
而是在验证：

  projection-aware 3D support
  + bridge095 partial b0
  是否能把 t0.90 从 0.4667 推过 q_vis 0.4741。


4. 当前 projection-aware 的限制

已做：

  voxel / latent cell
  -> project to masks
  -> 得到 3D support feature

未做：

  voxel / latent cell
  -> project to image feature map / token
  -> per-cell image feature sampling / cross-attention

所以当前版本是合理的下一步，但仍是中间版本。

它能验证：

  3D cell 级可见性 / mask 支持
  是否能改善 high-t。

如果效果有限，后面才需要上更强的 token-level projection，
或者更接近论文规模的 G_inp 训练。

       先做 partial b1 小步实验；
       即 b0 peripheral + last 1 transformer block；

  3. 如果 partial b1 仍不能让 t0.90 过 q_vis：
       再考虑改 projection-aware 结构。

为什么不直接改 aware 结构？

  因为更强 projection-aware 结构会引入很多新变量：
    crop 后 intrinsic 变换；
    image feature map / token 坐标；
    per-cell token sampling；
    memory / speed；
    token-level fusion 方式。

  如果现在直接改，结果变好或变差都不干净：
    可能是 projection 更好；
    也可能是 G_inp capacity 仍不足；
    也可能是 token projection 坐标没对齐。

所以当前路线：

  projection-aware b0 s400
  -> partial b1
  -> 再考虑 token-level projection-aware。

除非 s400 结果明显显示：

  t0.90 完全不动；
  t0.85 也没有优势；
  threshold precision / component 也不再改善；

否则不建议马上换 aware 结构。
