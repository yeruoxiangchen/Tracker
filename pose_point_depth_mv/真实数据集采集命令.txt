真实数据集采集命令
==================

一、最快用法：只替换 DATA
==========================

先只读检查。下面不会启动模型，也不会写入重建结果：

cd /home/zjr/Tracker

DATA=/path/to/你的真实数据集

GPU=0 DRY_RUN=1 \
  bash pose_point_depth_mv/background_jobs/run_real_official_slat_retest_one.sh \
  "${DATA}"

确认输出中的 dataset、geometry_mode、view_selection_policy、model_step、
checkpoint_sha256 和 output_dir 都正确后，正式运行：

GPU=0 \
  bash pose_point_depth_mv/background_jobs/run_real_official_slat_retest_one.sh \
  "${DATA}"

默认组合为：

- official Native-SS step2000，EMA；
- official Native-SLat step25000，EMA；
- 8 个最终输入视角；
- object_spherical_farthest_valid_mask 球面最远点视角筛选；
- bf16，单张 GPU；
- 输出是定性真实数据重建，不自动升级为正式 benchmark 结论。

DATA 可以是以下任意一种路径：

1. 原始真实数据集目录；
2. 已有 reconstruction_report.json 的旧重建目录；
3. reconstruction_report.json 文件本身。

如果传入旧重建目录或 report，启动器会解析其中冻结的 dataset_dir 和几何模式，
但新建的重建默认使用新版球面分散策略，不会静默复用旧视角策略。


二、最常用的替换方式
====================

1. 默认 step25000
-------------------

DATA=/home/zjr/Tracker/pose_point_depth_mv/outputs/可视AR/datasets/20260811_120312_862

GPU=0 DRY_RUN=1 \
  bash pose_point_depth_mv/background_jobs/run_real_official_slat_retest_one.sh \
  "${DATA}"

GPU=0 \
  bash pose_point_depth_mv/background_jobs/run_real_official_slat_retest_one.sh \
  "${DATA}"


2. 复现 step8000 对照
---------------------

DATA=/home/zjr/Tracker/pose_point_depth_mv/outputs/可视AR/datasets/20260811_120312_862

MODEL_STEP=8000 GPU=0 DRY_RUN=1 \
  bash pose_point_depth_mv/background_jobs/run_real_official_slat_retest_one.sh \
  "${DATA}"

MODEL_STEP=8000 GPU=0 \
  bash pose_point_depth_mv/background_jobs/run_real_official_slat_retest_one.sh \
  "${DATA}"


3. 同一数据集重新运行但保留旧结果
-----------------------------------

不要删除旧目录。只改 RUN_TAG，让新旧结果具有不同 identity：

DATA=/path/to/你的真实数据集

RUN_TAG=spherical_v2 GPU=0 DRY_RUN=1 \
  bash pose_point_depth_mv/background_jobs/run_real_official_slat_retest_one.sh \
  "${DATA}"

RUN_TAG=spherical_v2 GPU=0 \
  bash pose_point_depth_mv/background_jobs/run_real_official_slat_retest_one.sh \
  "${DATA}"


三、参数说明
============

DATA
  唯一必填项。原始数据目录、旧重建目录或 reconstruction_report.json 均可。

GPU
  物理 GPU 编号，默认 0。本流程是单卡推理，不要写成 0,1。

DRY_RUN
  设为 1 时只解析数据和打印最终命令，不启动 CUDA，不生成重建结果。

MODEL_STEP
  可选 25000 或 8000，默认 25000。启动器会把 checkpoint、期望 step、
  SHA256 和对应 predicted-support bridge 作为一组锁定，不能混搭。

RUN_TAG
  输出目录尾部标签，默认 spherical_v1。重测同一数据集时修改此值，避免覆盖。

SEED
  推理种子，默认 42。

OUTPUT_ROOT
  默认：
  /home/zjr/Tracker/pose_point_depth_mv/outputs/可视AR

SESSION_ID
  通常不需要填写。默认根据 MODEL_STEP、数据集名、SEED 和 RUN_TAG 自动生成。

GEOMETRY_MODE
  可选 point_mask 或 pose_mask。启动器通常可自动判断：

  - 手机采集并含 capture_report.json：pose_mask；
  - 依赖 COLMAP 稀疏物点的旧数据：point_mask；
  - 旧重建目录：沿用 report 中记录的几何模式。

VIEW_SELECTION_POLICY
  新数据默认 object_spherical_farthest_valid_mask。只有为了精确复现历史结果时，
  才显式指定 object_azimuth_balanced_valid_mask 或旧 lexical 策略。

GRAVITY_UP_W
  pose_mask 手机数据默认 0 1 0。它用于重力一致性质量门，不替代 runtime-O
  中的坐标变换。

MIN_OBJECT_POINTS
  point_mask 的物点下限；全新数据默认 32。若 DATA 能关联到旧
  reconstruction_report.json，启动器会保留 report 中冻结的历史值。旧的低质量
  CoarseModel 诊断数据可能只能设为 8；这只能作为定性诊断，不能视为合格输入。

MIN_MASK_OBSERVATIONS
  point_mask 中物点至少被多少个前景 Mask 支持；全新数据默认 2，旧 report
  存在时保留其历史值。

MIN_MASK_SUPPORT_RATIO
  point_mask 的前景支持比例门；全新数据默认 0.50，旧 report 存在时保留其值。

常见覆盖示例：

DATA=/path/to/你的真实数据集

GEOMETRY_MODE=pose_mask \
GRAVITY_UP_W="0 1 0" \
RUN_TAG=phone_spherical_v1 \
GPU=0 DRY_RUN=1 \
  bash pose_point_depth_mv/background_jobs/run_real_official_slat_retest_one.sh \
  "${DATA}"

五、采集与视角筛选规则
====================

离线最终筛选策略为：

object_spherical_farthest_valid_mask

它不是按文件名等间隔取帧，也不只看水平 azimuth。流程为：

1. 在与 runtime-O 一致的去畸变图像域中剔除前景 Mask 为空的帧；
2. point_mask 用合格稀疏物点的稳健中心估计物体中心；
3. pose_mask 用多帧 Mask 质心射线交会估计物体中心；
4. 把每个相机中心转成“物体中心指向相机”的单位球方向；
5. 用对象身份和帧名的 canonical SHA256 确定可复现的候选起点；
6. 贪心选择与已选集合最小夹角最大的帧，直到得到 8 帧；
7. 手机 pose_mask 在连续轨迹段内生成最多 32 个确定性候选集合；
8. 最终由射线残差、重力/轨道一致性、azimuth 覆盖和最大空隙质量门选定。

这一策略与官方 ProObjaverse 缓存使用的球面 max-min 分散原则一致。它有新的
策略名和 build_config identity，不会把旧 cache 静默当成新 cache。


六、手机实时采集建议
====================

手机端使用同一原则的在线近似，只负责减少重复帧：

- enablePoseDiverseCapture = true
- assumedObjectDistanceMeters = 0.70
- minimumPoseDiversityAngleDegrees = 10
- recommendedPoseDiverseFrameCount = 24

录制方法：

1. 始终让物体尽量保持在画面中心；
2. 围绕物体平移，不要只站在原地旋转手机；
3. 除水平环绕外，加入若干高、低俯仰角；
4. 至少采集约 24 张被接受的分散候选帧；
5. 如果界面提示角度过近，继续移动后再拍；
6. 保证光照和曝光尽量稳定，避免强运动模糊与大面积遮挡。

手机端首帧会沿相机前向临时估计一个 0.70 米物体中心；后续候选与已上传方向
至少相差 10 度才上传。只有上传成功的帧才提交方向。每个接受帧的临时中心、
球面方向、最小夹角和阈值会写入 frame_metadata.jsonl 的：

pose_diverse_capture

手机开始录制时还没有完整 Mask，所以手机端中心只是在线节流近似。服务器完成
分割后，必须再次用离线球面算法重估中心并权威筛出最终 8 帧。绝不能把手机端
临时中心直接当成 runtime-O 的坐标原点。

使手机端更新生效，需要：

1. 把更新后的 ARposeTTracker.cs 放入 Unity 工程；
2. 重新构建并安装 APK；
3. 重启使用 trellis_point_prior_mv/server.py 的采集服务。


七、坐标系合同
==============

视角筛选只改变“选择哪些输入帧”，不改变坐标数学。

最终输出仍以 runtime-O 缓存中的 T_O2W 为唯一权威来源：

runtime-O Mesh
  模型推理直接产生的对象规范坐标 Mesh。

world/AR Mesh
  由经过审计的 T_O2W 把 runtime-O Mesh 变换到采集世界坐标。

禁止：

- 根据预览结果手工补一个旋转或平移；
- 用手机端临时物体中心替换 T_O2W；
- 修改 checkpoint、Native-SS report、bridge report 或 freeze；
- 为了让重建通过而关闭 artifact identity 检查。

九、分步重建：仅用于调试
========================

正常使用时应优先运行文档开头的一路径启动器。下面把同一流程拆开，适合定位
具体是 raw cache、runtime-O、DINO、模型推理还是世界坐标打包失败。

以下示例按手机 pose_mask、step25000 编写。这里的 DATA 必须是原始数据集目录，
不能是旧 reconstruction 目录；只有文档开头的总启动器会自动反解旧 report。
先只修改 DATA、GPU 和 SESSION_ID。每一阶段都要成功并产生 passed=true 的
manifest/report 后，才执行下一阶段。


步骤 0：公共变量与环境
----------------------

cd /home/zjr/Tracker
set -euo pipefail

PY=/home/zjr/anaconda3/envs/reconviagen/bin/python
DATA=/path/to/你的真实数据集
GPU=0
SESSION_ID=manual_real_step25000_你的数据集名_seed42_spherical_v1
OUTPUT_ROOT=/home/zjr/Tracker/pose_point_depth_mv/outputs/可视AR
RUN=${OUTPUT_ROOT}/reconstructions/${SESSION_ID}

RAW=${RUN}/01_raw_cache
RUNTIME=${RUN}/02_runtime_o
DINO=${RUN}/03_dino_only_input
INFER=${RUN}/04_no_vggt_inference
BUNDLE=${RUN}/05_world_mesh_bundle

SS_REPORT=/data/zjr/proobjaverse_official_native_ss_train2000_20260815_v1/dev64_step2000_eval16_64_seed424344_6gpu_v1/aggregate_v1/report.json
SLAT_CKPT=/data/zjr/slat_train2000_trajectory_archives/slat_train2000_trajectory_step10000_25000_strict_fix1_v1/checkpoints/step_025000.pt
BRIDGE=/data/zjr/proobjaverse_official_slat_train2000_20260813_v1/eval_trajectory_step15000_20000_25000_seed424344_5gpu_strict_fix1_v1/step_025000/dev48_predicted/aggregate_v1/report.json
STOCK_FREEZE=/data/zjr/native_slat_genrecon_v2_mixed1k_20260802_v1/stock_slat_freeze_v2.json

export CUDA_VISIBLE_DEVICES=${GPU}
export TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
export ATTN_BACKEND=flash_attn
export SPCONV_ALGO=native

test -d "${DATA}"
test -s "${SS_REPORT}"
test -s "${SLAT_CKPT}"
test -s "${BRIDGE}"
test -s "${STOCK_FREEZE}"

ACTUAL_SHA=$(sha256sum "${SLAT_CKPT}" | awk '{print $1}')
test "${ACTUAL_SHA}" = 5092422900fe7d1e467684f0168aaa2cce67c754f6a48ff33d91c3772b2bcf58

test ! -e "${RUN}"
mkdir -p "${RUN}"


步骤 1：构建原始图像、相机和 Mask 缓存
---------------------------------------

"${PY}" -u -m pose_point_depth_mv.dataset_tools.prepare_coarsemodel_real_raw_cache \
  --dataset "${DATA}" \
  --output_dir "${RAW}" \
  --min_registered_pairs 8 \
  --allow_empty_points \
  --resume

"${PY}" -m json.tool "${RAW}/raw_cache_report.json" | tail -n 80

说明：pose_mask 手机数据允许没有可用稀疏物点，所以使用 --allow_empty_points。
如果明确是 point_mask 数据，应删除这个选项，并保证 COLMAP 稀疏点和相机有效。


步骤 2：构建 runtime-O，并筛选最终 8 视角
------------------------------------------

"${PY}" -u -m pose_point_depth_mv.dataset_tools.prepare_omni_real_runtime_inputs \
  --raw_cache_report "${RAW}/raw_cache_report.json" \
  --output_dir "${RUNTIME}" \
  --selected_view_count 8 \
  --view_selection_policy object_spherical_farthest_valid_mask \
  --geometry_mode pose_mask \
  --gravity_up_w 0 1 0 \
  --min_completed_objects 1 \
  --resume

"${PY}" -m json.tool "${RUNTIME}/runtime_input_manifest.json" | tail -n 120

point_mask 数据应把 geometry_mode 改为 point_mask，删除 --gravity_up_w，并增加：

  --min_object_points 32 \
  --min_mask_observations 2 \
  --min_mask_support_ratio 0.50


步骤 3：提取 DINO-only 条件
---------------------------

"${PY}" -u -m pose_point_depth_mv.dataset_tools.prepare_omni_real_dino_only_model_inputs \
  --runtime_input_manifest "${RUNTIME}/runtime_input_manifest.json" \
  --output_dir "${DINO}" \
  --device cuda \
  --resume

"${PY}" -m json.tool "${DINO}/model_input_manifest.json" | tail -n 100


步骤 4：official Native-SS step2000 + Native-SLat step25000 推理
----------------------------------------------------------------

"${PY}" -u -m pose_point_depth_mv.infer_real_proobjaverse_official_ss_slat \
  --model_input_manifest "${DINO}/model_input_manifest.json" \
  --native_ss_report "${SS_REPORT}" \
  --native_slat_checkpoint "${SLAT_CKPT}" \
  --expected_slat_step 25000 \
  --cross_deployment_bridge_report "${BRIDGE}" \
  --stock_slat_freeze "${STOCK_FREEZE}" \
  --output_dir "${INFER}" \
  --seeds 42 \
  --weights ema \
  --amp_dtype bf16 \
  --device cuda

"${PY}" -m json.tool "${INFER}/inference_manifest.json" | tail -n 120


步骤 5：用经审计的 T_O2W 打包 runtime-O 与 world/AR Mesh
----------------------------------------------------------

"${PY}" -u -m pose_point_depth_mv.package_real_proobjaverse_official_ss_slat_results \
  --inference_manifest "${INFER}/inference_manifest.json" \
  --runtime_input_manifest "${RUNTIME}/runtime_input_manifest.json" \
  --raw_cache_report "${RAW}/raw_cache_report.json" \
  --output_dir "${BUNDLE}"

"${PY}" -m json.tool "${BUNDLE}/report.json" | tail -n 120

分步命令到这里已经生成经审计的 Mesh bundle。完整入口还会继续物化 final/ 下的
OBJ、GLB、轨道预览和 contact sheet，并写 reconstruction_identity.json、
reconstruction_report.json、progress.json。为避免人工复制内部预览逻辑，若需要
标准完整输出，仍应回到本文开头的一路径启动器，用新的 RUN_TAG 运行；不要手工
拼接坐标转换或覆盖这个分步调试目录。
