## 5. 正式大数据渲染前的要求

### 5.1 GPU 预算

项目自身的数据构建与模型训练合计最多使用 4 张 GPU：

```text
render workers + model workers <= 4
```

启动前必须检查其他用户进程，不能仅按显存空闲推断卡可用。

### 5.2 渲染冻结参数

已通过 pilot 的主参数为：

```text
renderer                 = blender
engine                   = CYCLES
cycles device            = CUDA
image size               = 512
candidate views          = 24
selected views           = 8
sequences per object     = 2
frame selection          = mask_pose_diverse
Blender samples          = 16
bounds tolerance         = 0.001
trajectory               = ar_random
```

正式版本必须继续记录：

- source manifest 与代码 SHA256；
- Blender binary/script SHA256；
- 每个 shard 的 task inventory；
- renderer bounds audit；
- failure taxonomy；
- accepted/failed sequence 和对象数；
- low-texture、projection、framing 与 source-asset rejection。

### 5.3 失败处理

允许跳过的数据失败：

```text
source_asset_rejected
geometry_rejected
appearance_rejected
frame_selection_rejected
projection_rejected
```

不允许静默跳过的基础设施失败：

```text
renderer process crash
CUDA/Blender unavailable
task inventory mismatch
manifest/marker 不一致
路径或 source binding 改变
```

### 5.4 新增语义单物体门

旧的 A/B/C 只反映 geometry count、长宽比、dominant component 等几何启发式，不足以
判断单物体。例如：

```text
坏的航拍场景碎片:
  geometry_count       = 13
  aspect_ratio         = 8.95
  dominant_area_ratio  = 0.12

可接受的主体+小地面:
  geometry_count       = 13
  aspect_ratio         = 2.50
  dominant_area_ratio  = 0.69

坦克:
  geometry_count       = 6
  aspect_ratio         = 3.27
  dominant_area_ratio  = 0.46
```

所以不能用 `geometry_count > N` 直接拒绝。新的筛选顺序是：

1. hard invalid：文件缺失、不能解析、空 mesh、NaN/Inf、零面积；
2. scene-risk ranking：极端长宽比且 dominant ratio 很低等组合；
3. 四视图低成本预览；
4. 语义标签：
   - `keep_single_subject`；
   - `uncertain_review`；
   - `reject_scene_or_fragment`；
5. 只有 keep 对象进入正式 24→8 多视图渲染。

## 8. 数据代码重构路线

### D0：统一 manifest contract

统一 Objaverse/Omni/后续真实数据的字段：

```text
uid
object_uid
dataset_source
semantic_subject_label
source_mesh
frames[].image/mask/intrinsic/extrinsic
SS latent binding
source manifest SHA256
```

允许 frame/sample 绝对路径，不在训练代码中按来源写特判。

### D1：object-balanced 与 source-aware sampler

旧 sequence-balanced 会使多 sequence 对象被放大。新 sampler 必须：

- 先采 object；
- 再采 sequence；
- 可设置 Objaverse/Omni/source 比例；
- 报告每来源和每语义层级的实际 sampling histogram。

### D2：不可变 split

split 单位至少为 `source_glb/source_mesh`，并增加近重复审计。任何对象不能因为渲染失败
而从 holdout 被替换。

### D3：cache identity

所有 cache 绑定：

- reviewed manifest SHA256；
- object UID hash；
- source mesh hash；
- frame/image/mask hash或不可变 manifest binding；
- coordinate convention；
- encoder/checkpoint/code SHA256。

旧 897 cache 不得被伪装成 Mixed1k cache。未变化的 SS latent 文件可以复用，但必须在新
cache 中重新绑定和审计；pose lifting、support 和 object sampling cache 必须重建。

## 9. SS 结构重构与重训路线

当前主线不再只是继续调 Direct-SLAT residual。依据审计第 76 节，目标结构为：

```text
posed multiview image/point/depth evidence
-> native SS 16^3 spatial condition
-> corrected SS rollout
-> native SLAT sparse 32^3 spatial condition
-> every-block zero-init injection
-> Mesh
```

### S0：未训练 lifting 与坐标门

训练前必须证明：

- image/mask/intrinsic/extrinsic 与 source mesh 对齐；
- projected evidence 落在正确 16³ voxel；
- correct pose/depth 优于 shuffled pose/depth；
- Objaverse 与 Omni 坐标定义一致；
- condition disabled 时 exact stock fallback。

### S1：SS adapter-only

先冻结 native SS base，使用 zero-init spatial adapter：

- 在 native 16³ SS blocks 注入 pose-projected condition；
- 第一版不同时训练通用 LoRA；
- stock fallback 必须值等价；
- correct condition、wrong condition、condition dropout 都要记录。

### S2：小规模训练顺序

```text
8 objects   overfit/graph smoke
64 objects  mechanism + rollout smoke
reviewed ~1k full small training
```

旧 step900 可作 warm-start 对照，但主线不续接旧 optimizer。每次数据语义变化都重建
object-balanced data cursor 和 cache identity。

### S3：SS 验证门

按顺序要求：

1. teacher-forced target gain；
2. native schedule same-noise rollout；
3. occupancy/coordinate accuracy；
4. corrected-coordinate Mesh；
5. 2/4/8 nested views；
6. seeds 42/43/44；
7. Objaverse/Omni 分来源报告。

teacher gain 只能筛 checkpoint，不能替代 rollout/Mesh。

## 10. SLAT 结构重构与重训路线

### L0：重新生成 support

使用新 SS checkpoint 和 reviewed manifest 重新 rollout corrected support。不得把旧
step900 support cache 直接接入新 SS。

### L1：native 32³ every-block condition

在 active sparse 32³ coordinates 上采样 pose/SS evidence，并为各个 native SLAT block
配置独立 zero-init projection。第一版：

```text
adapter-only
native SLAT base frozen
native decoder frozen
```

不先假定 decoder 是瓶颈。只有 target-decoder audit 证明 latent 改善无法转为 Mesh，才
讨论小范围解冻 decoder。

### L2：LoRA/full 解锁条件

只有 adapter-only 在多 seed same-noise Mesh 上稳定优于 stock，才测试：

```text
LoRA-only
adapter-only
Full
```

若 Full 低于 adapter-only，应部署 adapter-only 或停止组合，而不是继续增加步数。

### L3：常显存 rollout

保留 V5.1 已验证的常显存策略：

- 每次只保留当前 rollout state；
- state 间 detach；
- deterministic horizon 不得同时保留 8 个完整 DDP graph；
- 24GB GPU 上先做 horizon/memory smoke；
- checkpoint 必须支持 optimizer-boundary resume。

## 11. 重训练执行门

### T0：不启动长训的条件

任一项成立时停止：

- reviewed manifest 未冻结；
- loader/source/tier 分层 smoke 未通过；
- correct pose/depth lifting 不优于 control；
- exact stock fallback 不成立；
- 64-object rollout/Mesh 没有可重复正趋势；
- GPU 总预算超过 4；
- 数据构建同时占用会导致训练 OOM 的卡。

### T1：约 1k 小训练

第一阶段目标不是论文最终结论，而是验证：

```text
新语义数据
+ native SS condition
+ native SLAT condition
```

是否能把 teacher/correct-support 优势稳定传到 rollout 和 Mesh。

### T2：扩量

只有 reviewed ~1k 满足探索门，再进入：

```text
约 3k scaling curve
-> 正趋势保持
-> 再决定是否渲染/训练完整 10k
```

不得因为 source-freeze 已完成就自动启动完整 10k 长训。

- source/tier stratified results。

### V2：最终 Mesh

```text
ReconViaGen original

Direct-SS only

```

指标：

- Chamfer-L1；
- F-score@0.02；
- normal consistency；
- largest component ratio；
- mesh success rate；
- component count；
- view reprojection silhouette/depth；
- 人工结构检查。

量化同时保留 rigid-pose canonical 与 shape-aligned 两种口径；人工图必须刚体对齐，不能
用非刚性对齐掩盖缺腿、错拓扑等结构错误。

```text
6 objects × 1 seed   = 快速诊断

```

4. 约 3k scaling curve 仍为正后，再决定更大比例真实训练。
