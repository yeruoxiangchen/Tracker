一、这条路线到底训练什么
======================================================================

定义：

VSS0 = ReconViaGen原生VGGT+DINOv2的 sparse_structure_vggt_cond
       + frozen Stock SS Flow

VSS  = VSS0
       + 当前Native-SS v2的known-pose posed-DINO 16^3条件
       + 每个SS Flow block前的zero-init projection
       + attention LoRA rank8/alpha16

本次只改变 Stock SS cross-attention 的输入context：

  no-VGGT旧路线 stock_condition
    -> native ReconViaGen get_ss_cond()产生的 ss_vggt_cond

严格保持不变：

- official Train2000/Dev64对象和顺序；
- 每对象冻结的相同8个view_ids；
- official SS target；
- posed-DINO visual features；
- official known K/T；
- VGGT预测camera/depth不进入训练；
- Native-SS v2 flow architecture、loss、LoRA、LR、EMA、随机1--8 views；
- per-rank batch=1，8卡grad_accum=1，global effective batch=8。

重要：SS与SLat的原生VGGT context不是同一种张量。

- SS必须使用 `get_ss_cond()` / `sparse_structure_vggt_cond`，形状固定为
  `[1,4096,1024]`；
- SLat使用 `get_slat_cond()` / `slat_vggt_cond`，不能拿来代替SS sidecar。

训练必须fresh Stock-equivalent初始化：

- 禁止resume旧no-VGGT Native-SS；
- 禁止使用旧mixed checkpoint作`--init_checkpoint`；
- 新optimizer、EMA、step和RNG轨迹全部从零开始；
- step0的数值基线必须是VSS0，而不是no-VGGT Stock floor。

`2000 steps`是基于前一条official SS经验冻结的首轮预算，不是预先保证的最优点。
最终仍以Dev16校准 + Dev48 held-out结果决定是否需要继续。

5. 训练退出后自动做原P9的report/checkpoint完整性守卫；

9. 两个SLat step都只用VSS0/VSS predicted support，official GT只作为量化target。

整个P6--P17不需要人工在cache、SS训练或任一评测结束后再输入第二条命令。
科学门`passed=false`会保留为负结果并继续；只有程序、identity、record matrix或
Stock-equivalence完整性失败才会中止流水线。

三、结果能说明什么、还不能说明什么
======================================================================

P10/P11直接回答：

  在完全相同native ss_vggt_cond下，
  VSS（posed-DINO+LoRA）相对VSS0（with-VGGT Stock SS）的occupancy/latent增量。

这比把旧no-VGGT Native-SS直接接到with-VGGT SLat更严格，因为SS自身的Stock
cross-attention domain已经恢复为ReconViaGen原生VGGT+DINO context。

它仍不能单独回答完整mesh端点是否更好。下一阶段应冻结：

  VSS step2000 EMA + frozen CFG
  -> 当前with-VGGT Native-SLat checkpoint
  -> 同一Stock mesh decoder

并在相同Dev48、相同seed、coordinate-keyed noise下，与N/N0/V0/R做paired mesh比较。
该下游bridge必须是独立评测，不能把SS occupancy gate直接写成完整mesh结论。


四、失败时的安全边界
======================================================================

- cache worker失败：保留输出和日志；原命令可resume完整对象，但不要手改sidecar/record；
- 1/2GPU smoke失败：保留独立smoke目录，不要拿它resume正式训练；
- 正式训练失败：只有checkpoint identity和resume合同核对通过后才可resume；
- Dev science RC=3：表示预注册科学门未过，不是程序崩溃；
- 任何阶段都不要修改旧no-VGGT cache/checkpoint/report或正在训练的with-VGGT SLat资产；
- 目前状态只能写“CPU/static ready；等待真实cache/CUDA smoke”，smoke真实通过后再升级结论。


五、VSS step2000 + with-VGGT SLat 的 Train64 / Dev48 predicted-support Mesh评测
======================================================================

这一节在with-VGGT SS与SLat训练、P10校准、P11 Dev48 SS评测全部完成后运行。

本节不运行任何“GT support作为SLat输入”的分支。三条固定分支是：

  A = VSS0 predicted support -> V0 Stock SLat
  B = VSS  predicted support -> V0 Stock SLat
  C = VSS  predicted support -> V  trained SLat

因此可以直接读：

  B-A：只隔离with-VGGT Native-SS的增量；
  C-B：在完全相同VSS predicted support上，只隔离trained SLat增量；
  C-A：当前完整with-VGGT VSS+V端点的端到端增量。

官方GT SLat/mesh只充当量化target，不作为任何预测分支的support输入。

Train64是训练重叠拟合诊断；正式Dev结果只取Dev[16:64)的48个对象，因为
Dev[0:16)已经参与VSS CFG校准，不能再写成held-out结果。
