ProObjaverse official SLat step10000：GT-support隔离曲线 + 新Native-SS Dev48端到端测试
====================================================================================

固定目的
--------

第一组（严格复现第144章的GT-support SLat隔离协议）：

  Train64：GT support，Stock SLat vs step10000 trained SLat
  Dev64：  GT support，Stock SLat vs step10000 trained SLat

  与已有step2000、step4000、step8000结果放在同一张表中横向比较。
  这四个checkpoint并不被表述为严格、连续采样的learning curve。

第二组（新official Native-SS predicted-support，Dev48）：

  A = Stock SS -> Stock SLat
  B = 新official Native SS step2000 -> Stock SLat
  C = 新official Native SS step2000 -> step10000 trained SLat

  报告中的三项差值分别是：

  stock_slat_mesh_transfer                  = B - A
  trained_slat_end_to_end_transfer          = C - A
  trained_slat_increment_on_native_support  = C - B

固定资源与强制执行顺序
----------------------

  1. 现有N9-5五个worker均已运行结束；是否结束以`complete=true`为准。
     shard0的`passed=false`是已记录的Mesh安全上限结果，不等于worker仍在运行。
  2. T3通过后，可以暂时跳过W0，先执行G0 -> G4；GT-support改用四卡4,5,6,7，
     与GPU3上的N9 shard0没有GPU重叠。
  3. G0仍应执行：它是CPU只读preflight，避免G1创建不可变输出后才发现合同问题。
  4. GT aggregate和N9五个worker都结束后，可直接执行P1；P1是完全自包启动段，
     会自己核对五份N9 report、Native-SS路径/SHA、旧service状态和GPU空闲量。
  5. W0和P0仅保留为可选的单独只读审计，不是P1的前置命令。
     predicted-support使用五卡3,4,5,6,7，启动后执行P2 -> P5。
  6. P6只是旧step8000与新step10000的只读对照，可在旧N10-5 aggregate存在后执行。
  7. G与N9 shard0虽然GPU隔离，仍会共享CPU、RAM和数据盘，速度可能略降但不改变评测语义。
     每个worker单GPU运行；“四卡/五卡”是对象分片并行，不是DDP。

固定统计协议
------------

  weights=ema
  joint_seeds=42,43,44
  surface_samples=20000
  amp_dtype=bf16
  GT-support：每个split 64 objects / 192 object-seed records
  predicted-support：Dev indices [16,64)，48 objects / 144 object-seed pairs

重要边界
--------

  - 第一组不执行Native SS；旧Native-SS report只用于验证step10000 checkpoint所冻结的训练合同。
  - 第二组才执行新official Native SS step2000，并比较A/B/C三条完整Mesh链路。
  - Train64是训练重叠拟合诊断；Dev64和Dev48是development，不是最终blind claim。
  - 不修改step10000 checkpoint、manifest、report、freeze或任何历史评测输出。
  - GT worker不支持中间结果resume；若形成partial目录，先审计日志，再换新输出后缀，禁止直接删除。
  - predicted-support worker支持`--resume`，中断后使用本文P3，不要重开新目录。
