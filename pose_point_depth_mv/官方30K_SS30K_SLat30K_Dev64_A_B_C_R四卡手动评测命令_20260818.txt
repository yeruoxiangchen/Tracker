official 30K：SS30K + SLat30K 在冻结 Dev64 上的 A/B/C/R 四卡手动评测
================================================================================

最简执行顺序
--------------------------------------------------------------------------------

  1. F39 只回传一次 frozen protocol 小包（P0-F39）。
  2. 源服务器下载并做路径 relocation（P0-SOURCE、P1）。
  3. 三卡（GPU 4/5/7）构建 bridge32、Dev64 compact cache（P2、P3）。
  4. 物化 official SS targets；bridge32 固定 CFG5；四卡做SS30K Dev64测试（P4--P6）。
  5. 四卡跑 Dev64 A/B/C（P7）。
  6. 四卡跑 strict ReconViaGen R，并直接复用 A/B/C 的精确 target NPZ（P8）。
  7. CPU 汇总 B-A、C-B、C-R（P9）。

本文件不提供自动串行长队列。每个 P 都是独立阶段；确认上一个阶段的程序与身份
完整后，再手动执行下一个阶段。P6 的科学门允许明确 FAIL 后继续候选端点评测，
但程序/对象矩阵/hash 不完整时不能继续。

默认使用物理 GPU 4,5,6,7。需要换卡时，在每个阶段 source 环境文件之前先写：

  export EVAL_GPUS=0,1,2,3

环境文件兼容三卡或四卡。P2/P3保留原有分片；P6/P7/P8在各自命令中显式
覆盖为GPU 4/5/6/7四卡，避免继承旧的三卡默认值。


一、科学定义
--------------------------------------------------------------------------------

本轮只测 SS30K checkpoint step30000 和 SLat30K checkpoint step30000；
不测 SS10K，不测 Train64，不测 GT-support SLat。
四条路线都从输入图像自行预测 sparse support；GT 只作为最终 Mesh 指标 target，
不会作为 SS/SLat 推理输入。

  A = posed-DINO 当前接口 -> Stock SS -> Stock SLat -> Stock Mesh decoder
  B = posed-DINO 当前接口 -> SS30K EMA -> Stock SLat -> Stock Mesh decoder
  C = posed-DINO 当前接口 -> SS30K EMA -> SLat30K EMA -> Stock Mesh decoder
  R = strict ReconViaGen：VGGT -> Stock SS -> Stock SLat -> Stock Mesh decoder

  B-A：SS30K 的组件增量（接口、Stock SLat、noise、decoder、target 固定）。
  C-B：SLat30K 的组件增量（SS30K support、noise、decoder、target 固定）。
  C-R：当前完整端点相对 strict ReconViaGen 的端到端收益；这是最重要结果。

C-R 同时改变输入接口、SS 和 SLat，不能把它解释成某一个组件的纯收益。

冻结协议：

  protocol SHA256
  86235b8039130c5c9e50f463e022142b967cf9d6d51089f049f434476e1218c6

  bridge32：与 train/dev/decoder-audit 均不重叠，只用于预注册 CFG5。
  Dev64：与 frozen train29872、实际 usable train29861 均不重叠。

  decoder_audit32 不进入本轮指标。它是训练前验证 frozen Stock decoder 与
  official target 合同的独立保留集；predicted_support_bridge32 才用于固定 SS
  部署超参数。最终 A/B/C/R 都只在同一 Dev64 上计分。

因此 Dev64 是完整 held-out development set；不是最终 untouched test set。

在 F39 执行：

  set +e
  (
    set -euo pipefail

    SRC=/root/autodl-tmp/proobjaverse_official_slat_protocol30k_seed20260813_v1
    OUT=/root/autodl-tmp/bootstrap
    NAME=ProObjaverse_30K_protocol_seed20260813_F39_20260818_v1
    OSS=oss://yxc814/proobjaverse-transfer/bootstrap

    test -s "${SRC}/protocol.json"
    test -s "${SRC}/predicted_support_bridge.json"
    test -s "${SRC}/dev.json"
    test -s "${SRC}/train.json"
    mkdir -p "${OUT}"
    test ! -e "${OUT}/${NAME}.tar.zst"
    test ! -e "${OUT}/${NAME}.tar.zst.sha256"

    /root/miniconda3/envs/reconviagen-bw/bin/python - "${SRC}" <<'PY'
import json, sys
from pathlib import Path
root = Path(sys.argv[1])
p = json.load(open(root / "protocol.json", encoding="utf-8"))
assert p["protocol_sha256"] == "86235b8039130c5c9e50f463e022142b967cf9d6d51089f049f434476e1218c6"

    s = json.load(open(root / f"{name}.json", encoding="utf-8"))
    assert s["protocol_sha256"] == p["protocol_sha256"]
    assert s["name"] == name and s["count"] == count and len(s["rows"]) == count

PY

    tar --use-compress-program='zstd -T0 -6' \
      -cf "${OUT}/${NAME}.tar.zst" \
      -C /root/autodl-tmp \
      proobjaverse_official_slat_protocol30k_seed20260813_v1

    (
      cd "${OUT}"
      sha256sum "${NAME}.tar.zst" > "${NAME}.tar.zst.sha256"
      sha256sum -c "${NAME}.tar.zst.sha256"
      zstd -t "${NAME}.tar.zst"
    )

    ossutil -e oss-accelerate.aliyuncs.com cp \
      "${OUT}/${NAME}.tar.zst" "${OSS}/${NAME}.tar.zst"
    ossutil -e oss-accelerate.aliyuncs.com cp \
      "${OUT}/${NAME}.tar.zst.sha256" "${OSS}/${NAME}.tar.zst.sha256"

P1：把 F39 split 的绝对路径严格 relocation 到源服务器 raw tree
--------------------------------------------------------------------------------

这里只改变绝对文件路径，不改变 UID、顺序或 protocol SHA。

  cd /home/zjr/Tracker
  set +e
  (
    set -euo pipefail
    source pose_point_depth_mv/background_jobs/source_proobjaverse_30k_dev64_abc_r_env.sh
    mkdir -p "${RELOCATED_PROTOCOL_DIR}"

    "${PY}" -u -m pose_point_depth_mv.relocate_proobjaverse_official_slat_split \
      --source_split "${F39_PROTOCOL_DIR}/predicted_support_bridge.json" \
      --selection "${SELECTION30K}" \
      --data_root "${RAW30K}" \
      --protocol_manifest "${F39_PROTOCOL_DIR}/protocol.json" \
      --expected_protocol_sha256 "${PROTOCOL_SHA}" \
      --expected_name predicted_support_bridge \
      --output "${RELOCATED_PROTOCOL_DIR}/predicted_support_bridge.json"

    "${PY}" -u -m pose_point_depth_mv.relocate_proobjaverse_official_slat_split \
      --source_split "${F39_PROTOCOL_DIR}/dev.json" \
      --selection "${SELECTION30K}" \
      --data_root "${RAW30K}" \
      --protocol_manifest "${F39_PROTOCOL_DIR}/protocol.json" \
      --expected_protocol_sha256 "${PROTOCOL_SHA}" \
      --expected_name dev \
      --output "${RELOCATED_PROTOCOL_DIR}/dev.json"

    "${PY}" - "${F39_PROTOCOL_DIR}" "${RELOCATED_PROTOCOL_DIR}" <<'PY'
import hashlib, json, sys
from pathlib import Path
f39, relocated = map(Path, sys.argv[1:])
def load(path): return json.load(open(path, encoding="utf-8"))
def uid_hash(rows):
    return hashlib.sha256(json.dumps([r["uid"] for r in rows], sort_keys=True,
        separators=(",", ":"), ensure_ascii=True).encode()).hexdigest()
bridge = load(relocated / "predicted_support_bridge.json")
dev = load(relocated / "dev.json")
train = load(f39 / "train.json")
assert bridge["protocol_sha256"] == dev["protocol_sha256"] == train["protocol_sha256"]
assert (len(bridge["rows"]), len(dev["rows"]), len(train["rows"])) == (32, 64, 29872)
assert uid_hash(bridge["rows"]) == "df0be6ac817efd98d829abb3b730939bebf2cb2ffeca07f171297ad7c8088a16"
assert uid_hash(dev["rows"]) == "d60751d4100c97c6944f05cce18723546613e16e54e83b36753bd02de1ba39dc"
assert uid_hash(train["rows"]) == "fe0e1cc4fb9970f1fb624fef2fbacbe091c319fda8ab4172b41d9e038e85ec04"
sets = [{r["uid"] for r in x["rows"]} for x in (bridge, dev, train)]
assert not sets[0] & sets[1] and not sets[0] & sets[2] and not sets[1] & sets[2]
assert all(Path(r["render_tar"]).is_file() and Path(r["slat_npz"]).is_file()
           for x in (bridge, dev) for r in x["rows"])
print({"passed": True, "bridge": 32, "dev": 64, "train": 29872,
       "all_disjoint": True})
PY
  )
  P1_RC=$?
  echo "P1_RC=${P1_RC} (0=PASS)"
  echo "current terminal remains open"

停止/恢复原则
--------------------------------------------------------------------------------

本流程没有跨 P 自动调度器。停止某个阶段时，只 kill 对应 tmux session，例如：

  tmux kill-session -t abc30k_dev64_2

P2/P3 compact worker 与 P7/P8 worker 都提供内容绑定的复用能力；恢复时只重新执行
相同 worker 命令，并保留 `--resume` 的阶段不得换 output path 或 scientific 参数。

P5/P6 official SS evaluator不是逐记录 resume 设计。若某个 SS shard 程序异常中断，
保留失败目录作证据，并换一个明确的新版本 output root 重跑；不要把不完整目录伪装成
完成结果。
