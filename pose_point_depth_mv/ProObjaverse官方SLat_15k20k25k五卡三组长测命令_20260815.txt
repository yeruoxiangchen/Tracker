ProObjaverse official SLat 15k/20k/25k：五卡三组无人值守评测
=======================================================================

目标
----

一次启动后，按step15000 -> step20000 -> step25000依次完成三组评测：

  tmux new-session -d -s slat152025eval \
    'EVAL_GPUS=3,4,5,6,7 bash /home/zjr/Tracker/pose_point_depth_mv/background_jobs/run_proobjaverse_slat_trajectory_eval_5gpu.sh'
    
  1. Train64 + official GT SLat support
  2. Dev64 + official GT SLat support
  3. Dev64中未参与Native-SS CFG校准的[16,64) Dev48
     + 新official Native-SS step2000 EMA / CFG5 predicted support

每组都分成五个不重叠的单GPU shard并行。共九wave、四十五个worker；
同一wave内五卡并行，wave之间自动等待、聚合并进入下一组。

重要科学边界
------------

  - GT-support的Train64和Dev64都是完整64对象。
  - Native-SS report只冻结了Dev indices [16,64)。前16个对象用于CFG校准，
    不能伪装成held-out predicted-support结果；因此第三组严格称为Dev48。
  - 第三组每个checkpoint都输出：

      A = Stock SS -> Stock SLat
      B = New official Native SS -> Stock SLat
      C = New official Native SS -> 当前trained SLat checkpoint

    以及 B-A、C-A、C-B三个配对transfer。
  - 已知support爆炸对象可能使predicted-support worker最终`complete=true,
    passed=false`。编排器会保留这个正式结果、照常聚合并继续后续wave，不会把它
    误判为程序崩溃。
  - 本测试不修改checkpoint、manifest、Native-SS report或stock freeze。

cd /home/zjr/Tracker

/home/zjr/anaconda3/envs/reconviagen/bin/python - "${ROOT}/trajectory_summary.json" <<'PY'
import json
import sys

report = json.load(open(sys.argv[1], encoding="utf-8"))
assert report["all_nine_aggregates_generated"] is True
assert len(report["results"]) == 9
assert {(row["step"], row["group"]) for row in report["results"]} == {
    (step, group)
    for step in (15000, 20000, 25000)
    for group in ("train64_gt", "dev64_gt", "dev48_predicted")
}
print(json.dumps({
    "all_nine_aggregates_generated": report["all_nine_aggregates_generated"],
    "all_runtime_integrity_passed": report["all_runtime_integrity_passed"],
    "result_count": len(report["results"]),
}, indent=2, ensure_ascii=False))
PY

cat "${ROOT}/trajectory_summary.txt"

注意：
  `all_nine_aggregates_generated=true`表示无人值守任务已完整产生九份聚合结果。
  `all_runtime_integrity_passed=false`可能是已知的80k support安全上限所致，不能据此
  把整个长任务误写为没有运行完。最终科学判读必须分别看Train64 GT、Dev64 GT
  和Dev48 predicted-support的完整metrics。


A6. 中断后重新执行规则
========================

  - 已完成的worker/aggregate会通过report identity校验后复用。
  - predicted-support的partial worker会自动加`--resume`。
  - GT-support evaluator当前不支持partial resume。如果中断时正处于GT wave，
    编排器会保护partial目录并拒绝覆盖；请先审计log，然后使用新的
    versioned `OUTPUT_ROOT`重跑，不要删除原失败证据。
  - 无中断时只需启动A3一次。
