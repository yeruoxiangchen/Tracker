说明
====

本流程从完整 Benchmark32 中固定随机抽取 8 例，并显式排除旧
`Benchmark32最佳2随机2_纹理几何与To2w世界投影_20260809_v1` 已选的 4 例：

  squash:squash_014
  carrot:carrot_027
  book:book_006
  tooth_paste:tooth_paste_009

排除不是手写对象过滤，而是绑定旧目录的 `选择清单.json` 及其 SHA256；脚本还会核对
旧清单和本次使用的是同一个 Benchmark32 report。随后从剩余 28 例中以固定 seed
`20260810` 无放回随机抽 8 例，不再挑“最佳”，不根据图像或指标人工换样。

按当前已绑定 report 预演得到的 8 例固定为：

  hand_cream:hand_cream_015
  banana:banana_045
  haw_thorn:haw_thorn_022
  ball:ball_013
  litchi:litchi_025
  toy_animals:toy_animals_011
  pear:pear_013
  potato:potato_032

本次渲染审查只输出两段“六种 Mesh 横向并排、同步环绕”的 MP4：

  渲染/六路同步环绕_自身纹理或顶点颜色.mp4
  渲染/六路同步环绕_统一材质几何.mp4

视频列顺序固定为：GT / 当前No-VGGT / 真实域Full / 合成域Full / ReconViaGen /
Pixal3D。72个环绕帧只在隐藏暂存目录生成；两段MP4成功编码并校验后立即清理，不在最终
审查包保留任何普通渲染PNG。原始OBJ/GLB也不复制到审查包，报告只记录源路径与SHA256；
GT带纹理坐标变换只在临时目录完成并在视频编码后清理。

唯一继续保留的PNG是“原始RGB上的物理世界坐标投影叠加”：逐方法/逐输入视图投影图和
`物理To2w_Tw2c投影到原始8视图对比.png`。输入8视图副本、GS注册接触表和普通渲染图
均不写入本次审查目录。当前No-VGGT所需GS重放资产放在独立cache目录，不混入审查包。

物理投影链继续固定为：

  Mesh_O -> 物理T_O2W -> Mesh_W -> 原始T_W2C
         -> K_raw + COLMAP相机畸变 -> 原始1920x1080 RGB

严禁用`T_O2C_lifting`代替物理`T_O2W/T_W2C`。本流程只做开发期定性观察，不修改
Mesh、T_O2W、相机、checkpoint、Benchmark32指标或Holdout64 formal结论。

R1. 输入报告与旧4例排除清单检查
===============================

cd /home/zjr/Tracker

PY=/home/zjr/anaconda3/envs/reconviagen/bin/python
REPORT=/data/zjr/omni_real_video500_download_20260804_v2/M9R_benchmark32_fiveway_with_records_20260809_v1/report.json
EXCLUDE=/home/zjr/Tracker/pose_point_depth_mv/outputs/可视化Mesh/Benchmark32最佳2随机2_纹理几何与To2w世界投影_20260809_v1/选择清单.json

"${PY}" -c \
  'import hashlib,json,sys
from pose_point_depth_mv.prepare_omni_real_holdout_mesh_review import select_cases
report_path,exclude_path=sys.argv[1:]
report=json.load(open(report_path)); old=json.load(open(exclude_path))
digest=hashlib.sha256(open(report_path,"rb").read()).hexdigest()
assert report["passed"] is True and report["formal"] is False
assert report["protocol_scope"]=="development_benchmark32"
assert int(report["object_count"])==32 and report.get("records")
assert old["final_report_sha256"]==digest
assert old["source_protocol_scope"]==report["protocol_scope"]
keys=[row["object_key"] for row in old["selected"]]
assert len(keys)==len(set(keys))==4
chosen=select_cases(report,top_count=0,random_count=8,random_seed=20260810,excluded_object_keys=set(keys))
chosen_keys=[row["object_key"] for row in chosen]
assert set(keys).isdisjoint(chosen_keys) and len(chosen_keys)==8
print(json.dumps({"passed":True,"benchmark_objects":32,"excluded":keys,"remaining":28,"selected":chosen_keys},indent=2,ensure_ascii=False))' \
  "${REPORT}" "${EXCLUDE}"
R1_RC=$?

echo "R1_RC=${R1_RC}"
echo "current terminal remains open"

R3. 中途终止后继续同一不可变目录
================================

2026-08-10恢复说明：首次R3在第一个对象`hand_cream:hand_cream_015`的Stock纹理GLB
烘焙处失败。原因是Gaussian evaluator的外层`torch.no_grad()`覆盖了TRELLIS `to_glb()`
内部需要`backward()`的texture Parameter优化；Mesh/Gaussian解码、随机8例选择和物理投影
合同没有失败。现已只在`to_glb()`局部使用`torch.enable_grad()`，公共TRELLIS代码和模型
推理仍保持不变。

第二次R3已完成全部2500步纹理优化，但旧临时路径以`.tmp-PID`结尾，`trimesh`把该后缀
误判为导出格式并报`exporter not available`。现已让临时路径继续以`.glb`结尾，同时显式
传入`file_type="glb"`并在异常时清理临时文件。

先重新运行R0，确认6项Gaussian测试和12项review测试通过，然后直接运行下面R3。不要删除
`OUT`、`GAUSSIAN_CACHE`或`选择清单.json`，也不要重新运行R2；`--resume`会校验既有
`run_config.json`，删除未原子提交的`.hand_cream_015.gaussian-building`后从同一8例继续。
