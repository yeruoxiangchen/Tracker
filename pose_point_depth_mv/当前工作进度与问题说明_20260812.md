# 当前工作进度与问题说明

更新时间：2026-08-12

这份文档只做项目交接用。目标是让没有参与全部实验的人，快速知道：现在的模型是什么、已经证明了什么、还没有证明什么，以及为什么手机采集结果还不稳定。

## 一句话结论

当前实际运行的候选 checkpoint 是 mixed real+synth No-VGGT 的 `step2000 EMA`：上游为 Native SS，下游使用带 posed-DINO/LoRA 增量的 Native-SLat 分支，最后接冻结 decoder。为了做清晰、可归因的科学比较，当前最可靠的主基线是同一个 Native SS 后接冻结 Stock SLat：

```text
RGB 多视角 + mask + 相机 K/T + 稀疏点云
        -> Native SS
        -> frozen Stock SLat
        -> 冻结的 Stock Mesh decoder
        -> Mesh
```

这里的 `frozen Stock SLat` 是证据和部署质量优先的主基线；实际运行的 Native-SLat/M8 分支是增加了额外条件和 LoRA 的候选分支，目前没有证明最终 Mesh 更好。

在 OmniObject3D 的正式 Holdout64 上，这个系统的几何指标明显优于 `ReconViaGen original pipeline`。但是这部分优势来自整个系统，不能全部归因于 Native-SLat；严格去掉全局位置、旋转和尺度后，当前 SLat 改动在小开发集上还没有证明有纯形状优势。手机真实采集目前的第一问题也不是继续加大训练，而是输入的相机轨迹、mask 和时间绑定没有稳定通过质量门。

## 1. 当前模型是什么

### 1.1 主流程

```text
手机或多视角 RGB
      + mask
      + 相机内参 K / 外参 T
      + 可选稀疏点云
              |
              v
      Native SS（预测 16^3 稀疏结构）
              |
              v
      转成实际的 32^3 SLat support
              |
              v
      SLat Flow（当前主基线为 frozen Stock SLat，25 步采样）
              |
              v
      冻结 Stock Mesh decoder
              |
              v
             Mesh
```

当前部署配置固定为：

- SS 和 SLat 都使用 `step2000 EMA`；
- 采样 25 步，CFG=5.0，CFG interval=`[0.5, 1.0]`；
- Mesh decoder 冻结；
- 默认质量优先输入是 `Point+Mask`；
- 手机部署候选是 `Pose+Mask`，也就是不使用稀疏点云，但它不是无损替代。

### 1.2 Native SS 在做什么

Native SS 是当前最有价值的改动。它把每个视图的 DINO 图像特征，按照相机 K/T 投影到 3D 查询位置，再在多个视图之间聚合，最后修改原版 SS Flow 对 16^3 稀疏结构的预测。

可训练部分主要是：

- SS attention LoRA：约 255.6 万参数；
- 3D posed-DINO 条件和聚合器：约 3358.4 万参数；
- 总可训练参数约 3614.0 万；
- 原版 SS 主干和 decoder 冻结。

### 1.3 Native SLat 和 Stock 的区别

这里容易混淆两个“Stock”：

- `Stock SLat`：冻结的原版 SLat Flow，只使用原版跨视图平均；
- `Native-SLat v2`：在 Stock SLat 基座上增加 LoRA、posed-DINO 3D condition 和学习式视图融合。

当前主基线建议仍使用：

```text
Native SS + frozen Stock SLat + frozen Stock decoder
```

这样可以单独证明 Native SS 的 support 改善能传到最终 Mesh。不能把这个 `Stock SLat` 叫成完整官方 ReconViaGen。

`ReconViaGen original pipeline` 是另一条完整官方链路，包含它自己的 VGGT/输入前端、Stock SLat 和 decoder。两者必须在报告中分开命名。

## 2. 相对 ReconViaGen 的当前结果

### 2.1 正式 Omni Holdout64：直接 runtime-O 几何

这是目前最正式的端到端结果：64 个对象、每个方法 20,000 个表面采样点、所有方法 Mesh 成功率都是 `64/64`。禁止 GT ICP、GT scale、GT translation 和 reflection fit。

| 方法 | Chamfer-L1（越低越好） | F@0.02（越高越好） | Normal（越高越好） |
|---|---:|---:|---:|
| 当前 Point+Mask | **0.070645** | **0.528586** | **0.789693** |
| 当前 Pose+Mask | 0.076963 | 0.527465 | 0.786867 |
| Real-adapted Full | 0.070206 | 0.530507 | 0.786992 |
| Synthetic-parent Full | 0.118620 | 0.203800 | 0.616984 |
| ReconViaGen original | 0.148510 | 0.121290 | 0.551080 |

当前 `Point+Mask` 相对 `ReconViaGen original`：

- Chamfer-L1 改善 `0.077865`，63/64 个对象获胜（98.44%）；
- F@0.02 提高 `0.407297`，63/64 获胜（98.44%）；
- Normal 提高 `0.238613`，61/64 获胜（95.31%）。

这说明在这套真实视频 Holdout 分布和直接 runtime-O 坐标合同下，当前系统相对 ReconViaGen 的几何优势很明确。

但要注意：这个差值同时包含真实域训练、Native SS、runtime-O 前端和 SLat/decoder 的整体作用，不能写成“Native-SLat 单独带来 50% 以上提升”。

### 2.2 去掉稀疏点云后的结果

正式 Holdout 上，`Pose+Mask` 相对 `Point+Mask` 的变化为：

- Chamfer-L1：差 `-0.006319`，Pose 胜率 43.75%；
- F@0.02：差 `-0.001121`，胜率 50.00%；
- Normal：差 `-0.002827`，胜率 34.38%。

所以点云不是外部优势的唯一来源，但去掉点云有小幅质量损失。Pose+Mask 仍然明显优于 ReconViaGen：Chamfer 胜率 98.44%，F@0.02 胜率 96.88%，Normal 胜率 93.75%。

部署解释应当是：

```text
Point+Mask：质量优先主模型
Pose+Mask：少一个点云采集环节的轻量候选，接受小幅质量交换
```

### 2.3 只看归一化形状时，结论要更谨慎

Holdout64 解盲后做了 M11S 事后补充：每个 Mesh 独立做 AABB 中心平移和最长边归一化，ReconViaGen 额外使用固定 decoder 轴变换；禁止逐对象 ICP、旋转搜索、反射和各向异性缩放。

| 方法 | Chamfer-L1 mean / median | F@0.02 mean / median | Normal mean / median |
|---|---:|---:|---:|
| 当前 Point+Mask | **0.041659 / 0.029769** | **0.462451 / 0.446349** | **0.788674 / 0.830768** |
| ReconViaGen original | 0.078514 / 0.074211 | 0.223246 / 0.200093 | 0.689863 / 0.672828 |

在这个 post-hoc shape-only 口径下，当前模型的 Chamfer 均值低约 46.9%，F@0.02 约为 ReconViaGen 的 2.07 倍，三个主指标胜率为 55--56/64。

这可以作为“归一化形状仍有优势”的补充证据，但不能重新称为 blind formal 结果，也不能用它证明世界坐标、物体放置或相机姿态更准确。

另外，第129章的 GT-assisted proper-Sim(3) 开发集只包含 16 个已消费对象。该口径允许更完整地消除全局旋转/尺度/平移后，`Stock2` 和 `Full2` 相对 ReconViaGen 的纯形状优势都没有建立。因此当前最稳妥的说法是：

```text
raw/runtime-O：优势明确；
固定规则归一化 shape-only：优势仍存在，但属于 post-hoc 补充；
严格 proper-Sim(3) 开发集：尚未证明稳定优势。
```

## 3. 当前训练遇到的问题

### 3.1 loss 变好，不代表最终 Mesh 变好

Native SS 的 teacher-forced 指标有正收益，但完整 free rollout 仍然退化：

- teacher Full-vs-Stock：`+0.083683`；
- rollout latent MSE：改善 `+0.009258`；
- rollout occupancy IoU：`-0.003263`；
- rollout recall：`-0.011890`；
- Full/Stock occupied count ratio：`0.93917`。

直白地说：训练时模型更接近 target，但经过真实采样和冻结 decoder 后，会删掉一部分本来正确的占用体素。当前训练目标和最终离散 Mesh 质量没有完全对齐。

### 3.2 residual 经常撞上上限

Native SS v2 的 residual 统计：

- raw guided delta ratio 平均 `0.28699`；
- cap 后 effective ratio 平均 `0.08493`；
- clip activation rate `84.4%`；
- 最后 100 step 的 clip activation rate `100%`；
- 最后 100 step raw ratio `0.35350`，effective ratio `0.09417`；
- RMS cap 固定为 `0.10`。

这表示模型经常输出过大的修正，再由 cap 压回去。它比较会判断“往哪边改”，但还不会稳定地判断“应该改多少”。

### 3.3 Native-SLat v2 没有把训练收益变成 Mesh 收益

在 32 objects x 3 seeds 的 N9 开发集：

- frozen Stock SLat Chamfer-L1：`0.052563`；
- Native-SLat v2：`0.052717`；
- 配对改善：`-0.000154`；
- F@0.02 delta：`-0.000449`；
- Normal delta：`-0.000373`；
- 两支 Mesh 都是 `96/96` 成功。

所以当前 Native-SLat v2 是“训练目标有收益，最终 Mesh 没有收益”，不能替换更稳定的 frozen Stock SLat。

### 3.4 Objaverse-only 二次训练没有超过 M8

Objaverse2K step2000 dev16 相对 M8：

- Chamfer-L1：`-0.000324`，对象胜率 31.25%；
- F@0.02：`-0.002864`；
- Normal：`+0.001762`，但 CI 跨 0。

step800 到 step2000 没有反转。当前更像是：

```text
M8 mixed(real+synth)
   -> 只用 Objaverse2K 继续微调
   -> mixed/真实域能力被覆盖或遗忘
```

因此不应只靠增加 Objaverse-only 步数解决，下一次应优先测试 mixed replay、参数/输出锚定或更低增量学习率。

### 3.5 M8 的优势不能全部归因于 SLat

在固定同一 SS support、同一噪声的 Objaverse16 SLat 隔离比较中：

- M8 Chamfer-L1：`0.120435`；
- Recon/Stock SLat：`0.120525`；
- M8 只在 `3/16` 对象上赢 Chamfer。

两者差距很小，说明 Omni 上的大幅提升主要来自 Native SS/support、真实域适配和输入前端的整体作用，而不是 M8 SLat 单独已经明显强于 ReconViaGen。

## 4. 真实手机采集时的问题

Omni Holdout 是真实视频和扫描数据，但不是手机 AR 采集。下面的问题会让手机端输入偏离训练/评测合同，所以不能把 Holdout64 数字直接当成手机端保证。

### 4.1 当前手机 manual8 输入明确不合格

`20260811_023209_578_manual8_v1` 的 8 帧虽然成功生成 Mesh，但使用了 diagnostic bypass，没有 GT，也没有正式 ReconViaGen 对照。

| 指标 | 手机输入 | 门限 | 结论 |
|---|---:|---:|---|
| 方位覆盖 | `206.749°` | `>=240°` | 失败 |
| 最大方位缺口 | `153.251°` | `<=120°` | 失败 |
| 方位间隔标准差 | `62.108°` | 需均匀 | 失败 |
| mask-ray median | `2.113077` | `<=0.2` | 失败 |
| mask-ray p90 | `4.701422` | `<=0.4` | 失败 |
| 最大相机位移跳变 | `4.109031 m` | 应连续 | 失败 |
| formal input | `false` | 必须 true | 失败 |

这次结果不能用来判断模型相对 ReconViaGen 的正式质量；它首先说明采集输入没有达到模型要求。

### 4.2 AR848：采集阶段通过，最终入模帧却没有通过

AR848 采集阶段 52/18 帧 QC 为：ray residual median `0.125206`、p90 `0.243326`，当时通过。但真正送入模型的 8 帧是：

- median `0.214896`，已经超过 `0.20`；
- p90 `0.315126`；
- `runtime_input_quality=null`；
- `formal_input_passed=null`。

原因是旧代码只对 `point_mask` 记录质量，`pose_mask` 分支可能跳过最终输入检查。第 0 帧还存在 SAM2 初始分割缺口；后续传播和裁剪没有制造该缺口，但也没有修复它。

### 4.3 只看方位覆盖会选到错误帧

Plant 64->8 的候选方位覆盖为 `246.981°`，表面上达到 `>=240°`，但 camera roll median 为 `124.026°`，正式输入仍为 false。原因是当时把 COLMAP `+Y` 强行当成 gravity，而 COLMAP 世界坐标没有保证这一点。

因此选帧不能只优化方位覆盖，还必须同时检查：camera roll、mask-ray residual、gravity 坐标合同、相邻轨迹是否连续、RGB/mask/pose 是否同一时间帧。

### 4.4 当前手机端的真实表现

当前手机系统已经能够跑通：

```text
手机 RGB/mask/K/T
 -> 8帧筛选
 -> Pose+Mask runtime-O
 -> DINO-only
 -> Native SS/SLat
 -> runtime/world Mesh
 -> AR Anchor 叠加
```

但本地无 GT 的人工观察显示，模型在附件、细长结构和细节完整性上仍可能弱于 ReconViaGen。当前回投影诊断的采样点凸包 IoU 约 `0.61391`；绕 Rx/Ry/Rz 180°后分别为 `0.60424 / 0.59836 / 0.61365`，没有证据表明统一的上下翻转可以解释问题。

AR Anchor 只能补偿 world origin 变化，不能修复 Mesh 自身的形状错误、比例错误、附件缺失和细长结构恢复失败。当前最像的主因是手机前端的 pose/mask/K/时间绑定和真实域几何误差，而不是 Anchor 单独造成的。

## 5. 现在应该怎么理解项目进度

### 已经比较确定的事情

1. Native SS/support 是当前最明确的有效改动；它能在冻结 Stock SLat 和 decoder 的情况下改善最终 Mesh。
2. 混合真实+合成训练在 Omni Holdout64 上保留了相对 ReconViaGen 的优势。
3. 去掉点云后，外部优势仍在，但相对 Point+Mask 有小幅正式退化。
4. 手机端完整链路已经打通，问题集中在输入质量和域外推，不是程序完全跑不起来。

### 还没有证明的事情

1. Native-SLat v2 没有证明相对 frozen Stock SLat 的稳定 Mesh 优势。
2. M8 的 Omni 优势不能写成“M8 SLat 单独优于 ReconViaGen”。
3. 严格 proper-Sim(3) 纯形状口径下，当前开发集还没有稳定超过 ReconViaGen 的证据。
4. Holdout64 不能直接证明任意手机 AR 采集都能达到同样质量。

### 当前优先级

1. 先修复手机端最终入模帧的质量门和轨迹合同：质量检查必须对真实消费的 8 帧执行，`formal_input_passed=false` 时禁止进入正式推理。
2. 修复 RGB/mask/pose 时间绑定、相机轴和 gravity 合同，再增加带高质量扫描参考的手机样本。
3. 训练上优先做 mixed replay、受控增量学习率和输出锚定；不要把 Objaverse-only 继续加步数当作默认解法。
4. 论文或对外报告中，主表使用 `Point+Mask`；`Pose+Mask` 报告为轻量化消融；`ReconViaGen original pipeline` 单独列名。

## 7. 对外建议用语

可以说：

> 在 OmniObject3D 的正式 Holdout64 上，当前 mixed No-VGGT 系统在统一 runtime-O 几何评测中明显优于 ReconViaGen original pipeline。去掉稀疏点云后，这一外部优势仍保留，但相对 Point+Mask 有小幅退化。当前主要收益来自 Native SS/support 和真实域混合训练；Native-SLat v2 单独的最终 Mesh 收益尚未建立。手机端目前优先需要修复输入轨迹、mask 和帧绑定质量，不能直接把 Holdout64 结果外推为手机端保证。

不要说：

> Native-SLat 单独已经全面超过 ReconViaGen；Pose+Mask 无损等价于 Point+Mask；或当前模型已经在任意手机采集上稳定优于 ReconViaGen。
