B1. 冻结正式 B protocol
======================

必须在代码最终确定后运行。protocol 会绑定实际工作树中的关键 Python 文件、
ReconViaGen sampler/SLAT/mesh decoder、checkpoint、Stage-A report/threshold、32 个样本的
cache/latent/GT/image/mask，以及 Trellis/VGGT/DINO/BiRefNet/DreamSim 实际权重的
SHA-256；不能只依赖当前 dirty worktree 的 git commit。B1 需读取较大的本地权重
文件，所以比普通配置写入慢是正常现象。

该命令还会生成权限为 0600 的 blind_key.txt。只向评分者提供 blind_pairs/ 和
blind_manifest.csv，不能提供 blind_key.txt、unblinding_key.json 或 report.json。

(
  set -uo pipefail
  cd /home/zjr/Tracker || exit 98

  PY=/home/zjr/anaconda3/envs/reconviagen/bin/python
  RUN=pose_point_depth_mv/outputs/direct_flow_p0_trainall_s1000_seed42_2gpu_bf16_v3
  ROLLOUT=${RUN}/eval_val_rollout32obj_step000900_seed424344_steps30_v1
  STAGE_A_PROTOCOL=${RUN}/protocols/val_rollout32obj_step000900_v1
  PROTOCOL=${RUN}/protocols/mesh_val32obj_step000900_seed424344_v1

    echo "B protocol already exists; do not silently overwrite: ${PROTOCOL}"

    --rollout_report "${ROLLOUT}/report.json" \
    --rollout_protocol_dir "${STAGE_A_PROTOCOL}" \
    --output_dir "${PROTOCOL}" \

    --deterministic_repeat_mesh_vertex_chamfer_l1_max 0.0001 \

B4. CPU cleanup diagnostic
==========================

这一段仅对 B3e 已导出的 stock/correct Mesh 做完全对称的 CPU 后处理诊断：
两个分支都使用相同的连通分量规则，对比 raw、仅保留最大连通分量、删除顶点数
小于 100 的组件三种策略，然后从各策略 Mesh 重算 Chamfer/F-score/normal/
mesh-structure 指标。不重新运行 SS/SLAT，不需要 GPU，不覆盖原始 OBJ；结果必须
视为 non-formal diagnostic evidence。

CPU_THREADS 可按机器负载调整，默认 8。如 OUT 已存在，命令会自动加入 --resume。
返回码 0 表示 192 条 raw/cleanup 记录、96 个配对、raw 口径复核和清理后盲化审计
均完整有效；返回码 2 表示诊断跑完但上述有效性检查至少一项未通过，不能静默当作成功。

(
  set -uo pipefail
  cd /home/zjr/Tracker || exit 98

  RUN=pose_point_depth_mv/outputs/direct_flow_p0_trainall_s1000_seed42_2gpu_bf16_v3
  SOURCE_OUT=${RUN}/mesh_val32obj_step000900_jointseed424344_exploratory_v1
  OUT=${RUN}/mesh_val32obj_step000900_jointseed424344_exploratory_cleanup100_v1
  LOG=${OUT}.log
  CPU_THREADS=${CPU_THREADS:-8}

  if [ ! -s "${SOURCE_OUT}/report.json" ]; then
    echo "missing exploratory source report: ${SOURCE_OUT}/report.json"
    exit 98
  fi

  RESUME_ARGS=()
  if [ -d "${OUT}" ]; then
    RESUME_ARGS=(--resume)
  fi

  OMP_NUM_THREADS="${CPU_THREADS}" \
  MKL_NUM_THREADS="${CPU_THREADS}" \
  OPENBLAS_NUM_THREADS="${CPU_THREADS}" \
  NUMEXPR_NUM_THREADS="${CPU_THREADS}" \
  VECLIB_MAXIMUM_THREADS="${CPU_THREADS}" \
  /home/zjr/anaconda3/envs/reconviagen/bin/python -u \
    -m pose_point_depth_mv.eval_mesh_cleanup_diagnostic \
    --source_output "${SOURCE_OUT}" \
    --output_dir "${OUT}" \
    --min_component_vertices 100 \
    --surface_samples 20000 \
    --bootstrap_samples 5000 \
    --workers "${CPU_THREADS}" \
    --export_cleaned_meshes \
    "${RESUME_ARGS[@]}" \
    2>&1 | tee -a "${LOG}"
  CODE=${PIPESTATUS[0]}

  echo "${CODE}" > "${OUT}.exit_code"
  echo "B4 CPU cleanup diagnostic code=${CODE}"
  exit "${CODE}"
)


B5. 盲评包与人工评分
===================

评分者只能收到：

  ${OUT}/blind_pairs/
  ${OUT}/blind_manifest.csv

`blind_pairs/` 内只包含 A/B artifacts，不包含 branch 名称、metrics 或 pair mapping。

禁止向评分者提供：

  protocol 的 blind_key.txt
  output 的 unblinding_key.json
  report.json、private_records/、completion_manifest.json

评分前冻结至少以下列：

  pair_id,rater_id,preference

其中 preference 只能为 A、B、tie、invalid。建议至少三名独立评分者；所有 96 个 pair
都必须展示，不能只挑改善样例。先固定 ratings.csv 的 SHA-256，再由非评分人员读取
unblinding_key.json 做解盲统计。


B阶段裁决
=========

Formal PASS 要求：

  1. 96/96 paired trials 完整，无 empty/nonfinite/export-failed pair；
  2. primary canonical Chamfer improvement（stock-correct）mean>0、median>0、
     object win>=0.55，object-bootstrap 95% CI lower>0；
  3. F-score@0.02 mean delta >= 0；
  4. Mesh success rate 不下降；
  5. largest-component ratio mean delta >= -0.02；
  6. 至少 2/3 joint seeds 的 object-mean Chamfer improvement 非负。

如果 B PASS：可以声称“该训练配置在 frozen validation 上相对 stock/base 改善最终
Mesh”，然后冻结全部协议并只运行一次 untouched holdout。

如果 B FAIL：保留全部产物并按 SS replay、SLAT、GT surface、碎片/连通性分层定位；
不得换 seed、删失败对象或按观感重选 step 1000。

即使 B PASS，由于 pose/depth corruption controls 与 correct 几乎相同，目前仍不能声称
收益来自正确 pose/depth correspondence。要做机制结论，必须另行预注册 controls 的完整
Mesh 导出并要求 correct 显著优于 controls。
