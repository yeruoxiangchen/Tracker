# Mixed1k 现有渲染数据预览、构建与重训重验证路线

更新时间：2026-07-30 UTC

## 1. 本轮数据边界

本轮不等待完整 10k 渲染，先复用已经实际生成且文件完整的数据：

- Objaverse：旧 897-object 训练集，1259 个 accepted sequences。
  - A：183 objects / 282 sequences。
  - B：531 objects / 737 sequences。
  - C：183 objects / 240 sequences。
- OmniObject3D：`pilot_omni256_cyclescuda_v4` 已完成的 4 个分片。
  - 123 个至少有一个 accepted sequence 的对象。
  - 232 个 accepted sequences。
- 合并后：1020 objects / 1491 sequences。

这里的 C 仍是“疑似 scene-like、需检查”，不是 hard reject。为尽量接近用户提出的 1k
规模，draft 版本暂时保留 C，但必须显式标记 `review_status=pending` 和
`formal=false`。

## 2. 100-object 抽检协议

抽样单位是 `object_uid`，不是 sequence。每个对象最多出现一次，然后从该对象的
accepted sequences 中随机选一条，再随机选一帧。

固定种子为 `20260730`，按完整 1020-object 组成用最大余数法分层：

- Objaverse A：18。
- Objaverse B：52。
- Objaverse C：18。
- Omni：12。

总计 100 个对象、100 张训练输入图。仓库内保存：

- 原始抽样图像副本；
- 10×10 contact sheet；
- 可放大检查的 HTML；
- 记录原始路径、对象、sequence、frame、SHA256 的 JSON；
- 可填写 `review_decision` 和 `review_note` 的 CSV。

这个抽检用于发现数据定义或来源级系统性错误，不等价于对全部 1020 个对象逐一完成人工
单物体认证。

## 3. 数据集构建方式

新数据集是不可变 manifest view，不复制 1491×8 张图和 latent：

1. 将 Objaverse、Omni 的 image、mask、SS latent 和 source mesh 路径规范化为绝对路径。
2. 保留每个 sample 的原有相机内外参、质量统计和 sequence 身份。
3. 新增：
   - `dataset_source`；
   - `single_object_tier`；
   - `source_manifest`；
   - `source_manifest_sha256`。
4. 合并前检查所有 mesh、latent、image 和 mask 文件存在。
5. 对 sample UID、object UID 做跨来源唯一性检查。
6. 冻结输入 manifest、897 audit 和四个 Omni shard manifest 的 SHA256。

当前加载器的 `_resolve` 已支持绝对路径，因此这个 view 可直接被现有多视图 loader 读取。
draft 只能用于 loader/cache smoke；人工检查通过后才派生新的 reviewed freeze，旧 manifest
和旧 cache 均不覆写。

## 4. 代码重构路线

### R0：统一数据契约

将后续 cache builder 收敛到同一个 source-manifest contract：

- sample/frame 允许绝对路径；
- `object_uid` 是采样和 split 的基本单位；
- source/tier 是必带元数据；
- split 前检查 mesh 级和 object 级去重；
- object-balanced sampler 取代 sequence-balanced sampler；
- 每次构建输出源文件绑定、对象列表哈希和 loader smoke 报告。

不把 Objaverse 与 Omni 复制到同一物理目录，也不在训练代码里写来源特判。

### R1：先重建 cache，禁止复用旧 897 cache

数据定义、对象分布和来源已经改变，因此以下内容都要从 reviewed Mixed1k manifest 重建：

- 多视图图像 condition/cache；
- pose lifting / correspondence cache；
- SS target/cache；
- Direct-SLAT support/cache。

第一步先取 8 objects 做完整 cache smoke，并审计图像、mask、相机、SS latent、source mesh
逐 UID 对齐；通过后再构建全量 1020 objects。

### R2：Direct-SS 重训

主线从 frozen native stock 和零初始化 adapter/LoRA 开始，不续接旧 optimizer。
旧 step900 可作为 warm-start 对照，不作为唯一主结果。

顺序：

1. stock exact-fallback 和 coordinate/frame audit；
2. 8-object overfit；
3. 64-object smoke；
4. Mixed1k 全量训练；
5. teacher-forced、rollout、same-noise mesh 三层门。

报告必须同时按 Objaverse A/B/C 和 Omni 分层，防止总体均值掩盖单一来源退化。

### R3：Direct-SLAT 重训

不能直接把旧 Direct-SLAT cache 接到新的 SS：

1. 用新 Direct-SS checkpoint 重新 rollout corrected support；
2. 审计 corrected support 与 native SLAT condition/decoder 的坐标和分布兼容性；
3. 重建 Direct-SLAT target/support cache；
4. 先训练 adapter-only；
5. adapter-only 在 same-noise Mesh 上稳定优于 stock 后，才增加 LoRA/full；
6. full 必须同时超过 stock 和 adapter-only，否则保留 adapter-only 部署分支。

teacher-forced gain 只用于筛 checkpoint，不能替代 Mesh 结论。

## 5. 重验证路线

### V0：数据与加载器

- 所有引用文件存在；
- UID 和 object UID 唯一；
- train/val/holdout object-disjoint；
- 随机可视化按来源、tier 分层；
- 相机投影、mask、source mesh 与 SS latent 对齐；
- loader 读取 Objaverse/Omni 混合 batch 的 smoke。

### V1：SS

- exact stock fallback；
- teacher-forced target gain；
- same-noise rollout；
- corrected-coordinate Mesh；
- 2/4/8 严格嵌套视角；
- seeds 42/43/44；
- 按来源/tier 给出均值、median、win rate 和 bootstrap CI。

### V2：SLAT

- stock、adapter-only、LoRA-only、full 同 noise；
- endpoint/rollout 指标；
- Mesh Chamfer-L1、F-score、normal consistency、component ratio；
- 结构性人工检查，特别关注薄结构、腿/角/把手和多组件对象。

### V3：端到端基线

固定同一输入、同一对象、同一视角协议，比较：

- ReconViaGen original；
- native stock；
- Direct-SS only；
- Direct-SS + Direct-SLAT；
- Pixal3D official final；
- GT/reference。

量化使用 rigid-pose canonical 和 shape-aligned 两套口径，人工图使用刚体对齐，不用非刚性
对齐掩盖缺腿、错拓扑等问题。

### V4：新鲜盲测

在所有结构、checkpoint、阈值确定后，再冻结从未参与开发的 object-disjoint holdout。
正式结论至少需要 32 objects × 3 seeds；6-object 结果只用于快速诊断和选择是否继续。

## 6. 当前可做与不可做

可以立即做：

- 检查 100 张抽样图；
- 对 draft manifest 做 loader/cache 小样本 smoke；
- 估算 cache、训练时长和显存。

暂时不可做：

- 把 C tier 或整套 Mixed1k 称为人工确认的纯单物体数据集；
- 复用旧 cache 后声称完成 Mixed1k 重训；
- 只凭 teacher-forced gain 宣称端到端 Mesh 提升；
- 在抽检结论出来前启动长训。
