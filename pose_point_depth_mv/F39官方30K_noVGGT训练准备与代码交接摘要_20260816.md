## 7. compact-cache-v2 的实际设计

旧 v1 会在 condition/lifting 等路径重复保存同一批 DINO 特征，还会序列化训练中不被数值使用的全零 depth/confidence/prior/occupancy 占位。30K 如果直接复制旧格式，预估可达约 2.45 TiB，不应构建。

compact-v2 的原则是不改变 runtime tensor 和训练数学：

- 每个对象只序列化一份 fp16 raw DINO patch features。
- 保存已知 official camera `K/T`、`view_ids`、image size 和 preprocessing identity。
- 不落盘全零 `corrected_ss` / `occupancy_logits64` / depth / confidence / prior 占位。
- Stock condition 与 positive/negative SLat context 由同一份 DINO 在 runtime 确定性重建。
- official LH-SLat target 依然直接引用原 `.npz`，不复制 target。
- SLat/lifting 两个 manifest 必须是同一 matched pair；UID、row order、config hash、pair identity 任一不符都立即失败。
- legacy-v1 仍使用原 `PoseLiftingCacheDataset` 路径，没有放宽旧合同。
- compact-v2 通过 `CompactNativeConditionBackend.lifting_view` 执行同一 `validate_dino_only_lifting_contract`，不再被 legacy lifting parser 错拒。

## 9. 当前 no-VGGT SLat 模型结构（简述）

本次 30K scaling 对象是 official ProObjaverse no-VGGT Native-SLat `architecture=v2`，不是 Native-SS 训练，也不是 with-VGGT 分支。

主要结构：

- base：frozen ReconViaGen/TRELLIS Stock SLat flow model。
- Stock cross-attention context：per-view raw DINOv2 patch tokens。
- 3D condition：使用 official 已知 `K/T` 将多视图 DINO 特征投影到 active 32³ sparse SLat coordinates。
- aggregation：当前 v2 `GenreconViewAggregator`。
- injection：在每个 SLat transformer block 前加入 zero-init independent condition projection。
- trainable surface：attention LoRA（rank 8 / alpha 16）+聚合/每 block condition projection；Stock base 保持冻结。
- target：official ProObjaverse LH-SLat GT coordinates/features。
- VGGT：不执行；不使用 VGGT feature/depth/camera。
- Native-SS：训练 cache 绑定一个冻结 upstream Native-SS deployment 作为 identity/evidence，但 GT-support SLat 训练使用 official target coords，compact builder 不现场执行 Native-SS。

应保持不变的 2K 对照合同：

- `p_uncond=0.1`。
- timestep schedule = uniform。
- random condition views = 1--8（parser 的通用 default 可能更大，正式 launcher 必须显式写 1/8）。
- bf16。
- gradient checkpointing = ON。
- per-rank batch = 1。
- world size = 8，grad accumulation = 1，global effective batch = 8。
- new-condition LR = `1e-4`，LoRA LR = `3e-5`，new-condition weight decay = `0.01`。
- EMA decay = `0.9995`。

30K no-VGGT scaling 应从 Stock-equivalent fresh initialization 开始；默认不 resume 2K step25K，因为那会把“增加数据”与“继承 2K optimizer/EMA/trajectory”混在一起。曾提议的 30K/60K/120K/150K checkpoint 是 matched-exposure 候选，不是已冻结 launcher；应先根据 pilot 和初期评测决定。

## 10. strict runtime 与 compact-v2 尚未合并的风险

当前有两类已有能力，但不能误以为它们已在同一个正式 runtime 中：

1. 根目录当前 official trainer 已支持 compact manifest/backend，但其共享 trainer 仍可见 legacy `DDP(device_ids=[local_rank])` 与基础 DataLoader 路径。
2. `a72_perf_v1_fix1_testcompat1/Tracker` 包含已在 A72 真实 CUDA 验证的 strict runtime：`DDP(device_ids=None)`、workers/persistent/prefetch/pin-memory、CPU-selected lifting 和严格 H2D policy。但该冻结参考树的 `NativeConditionSLatDataset` 早于 compact backend 接入。

因此，全量 30K 训练前还需要一个版本化的“compact-v2 + strict-fix1”运行闭包，或者明确决定先用功能正确但未优化的根 trainer 跑小 smoke。这个合并必须通过真实 1/2/8-GPU CUDA smoke，不能只靠 CPU unit tests。

作为性能参考，A72 strict-fix1 在相同 8-GPU/global-batch-8/thread-2 A/B 中把 legacy 稳定 step time 从 0.7925 s 降到 0.6536 s，吞吐提高约 21%。这个数字不能直接当成 RTX 6000D 的预期速度；F39 必须自己做短窗口 benchmark。
