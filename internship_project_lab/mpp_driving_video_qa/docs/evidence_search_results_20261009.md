## 2. 本次到底比较了什么

- 数据：固定开发集 4320 问／400 个 segment，其中 Action 3120 问、Scenery 1200 问。
- 搜索模型：`/data/zjr/models/Qwen3-VL-8B-Instruct`，BF16，每卡独立问题分片。
- 搜索输入：完整问题和原五帧；不包含参考答案、Judge 分数、失败标签或人工框。
- 工具循环：最多两轮、每轮最多五个原像素裁剪请求；看到实际裁剪图后选择最多
  五个证据区域，每个原帧最多两个。最终 MPP 输入最多十个视图。
- 下游 MPP：`outputs/mpp_feedback_sft_control_40k_2epoch_v2/final` 的语言 LoRA、
  projector 和完整 Q-Former；两组使用相同三路权重和加载精度。
- full：原五帧；evidence：原五帧加选中裁剪，带原时间索引及坐标说明。
  外部模型的答案、解释和 `purpose` 不传给 MPP。
- MPP：greedy、96 个新 token、batch size 1；评分沿用
  `official_lower_strip_maxref_logit_gt0_maxlength128_v1`。

2026-10-09 归档时逐题核对：两组各有 4320 个唯一 question ID，原问题、参考答案、
segment ID、预测与评分记录逐项一致。运行 manifest 的差别为 `region_condition`
及 evidence 组额外记录的裁剪编码器身份，模型／数据／生成预算一致。
该检查排除了明显的错配评测；它不能单独证明裁剪正确或推理实现不存在任何问题。

政策身份：`569d8d953948af7fd869e46bee32056280ca4795d1de9b2e5c5779ae5fbc9219`。

## 4. 搜证完成不等于证据有效

| 搜证状态 | 问题数 | 占比 | full 正确数 | evidence 正确数 | 配对修复／退化 |
|---|---:|---:|---:|---:|---:|
| selected：合法选择了裁剪 | 3378 | 78.19% | 2017 | 1824 | 286／479 |
| full_only：正常决定不追加 | 508 | 11.76% | 328 | 326 | 1／3 |
| failed：执行失败，回退原五帧 | 434 | 10.05% | 264 | 267 | 4／1 |

`selected` 只表示工具协议通过、裁剪确实返回且被选择，不是人工确认的目标身份
或“证据正确率 78.19%”。失败题仍在 4320 的分母中。

关键定位：**真正追加图像的 3378 问净退化 193 问（−5.7134 个百分点），
其 segment-bootstrap 95% 区间为 [−7.5739，−3.8416] 个百分点。**
没有追加图像的 942 问合计净增 1 问。因此，当前整体降分不能主要解释为
“434 次工具执行失败拖低了分数”；修好这些执行失败也不会自动消除成功选区组的退化。

942 个回退／不追加样本按代码使用与 full 相同的提示和原五帧。两次生成中
897 问答案逐字一致、45 问文字有变化，9 问 Judge 翻转（5 修复、4 退化）。
这提示仍有回放可复现性问题需要单独核验，具体数值来源尚未定位；不能把这些
没有追加图像的差异解释为视觉搜证收益。其净变化也远小于 selected 组的净退化。

## 5. 434 次执行失败的实际原因

以下统计来自逐题 `error` 与末次 `trace`，不是根据总失败数猜测：

| 第一处触发的失败 | 数量 |
|---|---:|
| 单轮请求数量超过 5 | 236 |
| 框坐标越界、顺序或非空性不满足 0–1000 协议 | 73 |
| 最终选择在同一原帧超过 2 个区域 | 71 |
| finish 字段不符合协议 | 17 |
| JSON 语法错误或输出多个对象等 | 13 |
| 最终总数超限或引用未观察 ID（合并校验项） | 11 |
| 未知 action，如 select 而不是 finish | 11 |
| 512 token 内未产生结束符 | 2 |
| 合计 | 434 |

236 次请求超量中，223 次一次要求 6 个裁剪；其余为 7 个（2次）、8 个（2次）、
10 个（7次）、11 个（2次）。框错误样例含 `[0,0,300,1280]`，混淆了原图像素
尺寸与 0–1000 坐标约定。finish 缺 `reason` 也会被当前严格协议拒绝，不能据此
断言图像内容一定无效。

本次失败列表没有 CUDA OOM、网络连接或模型加载异常。记录的最大搜索输入
为 3841 token，低于 6144 上限；输出截断只有 2 次。因此没有证据支持把主要
问题归为上下文太短、输出预算太小或下载未完成。

后续如继续该搜证器，协议修复可限定为：更明确的数量／坐标提示、校验错误回传后
的一次有限重试、无关说明字段的兼容处理。必须新开策略版本，不能静默改写旧结果；
更不能把含糊坐标直接截断成合法框，就声称恢复了正确证据。

## 6. 区域分布和成本

- 总搜索调用 10163 次，实际观察 18652 个裁剪；最终选中 9431 个区域槽，去重
  编码 7755 个 crop。7755 是缓存区域数，不是问答数或成功纠错数。
- selected 样本平均追加 2.79 个区域；全开发集平均 7.18 个 MPP 视图（含五帧）。
- 最终区域数分布：0／1／2／3／4／5 个分别为 942／924／1068／175／209／1002 问。
- 3378 个 selected 样本里，追加裁剪涉及 1／2／3／4／5 个原时间帧的题数分别
  为 1012／1073／178／186／929。只追加少数时刻并不等于丢失其他原帧，五帧仍保留；
  但动作题中局部目标是否跨帧一致，仍需视觉审核，不能由这些数量确认。
- 搜索逐题耗时均值 14.62 秒，p50 13.65 秒、p95 27.33 秒；这些是 worker 内逐题
  时间。四卡搜索阶段实际 wall time 为 16175.81 秒（约 4小时29分36秒）。
- 裁剪缓存阶段 wall time 229.05 秒；缓存自身 summary 记录 209.46 秒，两者
  起止范围不同，不混为同一个计时。
- full 生成 wall time 4277.07 秒；evidence 生成 4678.65 秒。两组评分分别
  118.87 秒和 119.36 秒。正式搜索到两组评测完成约 7小时07分。
- MPP 模型生成均值 full 965.68ms、evidence 1031.18ms；未包含搜索和缓存。
  没有测量在线端到端延迟，不能把约 1 秒的 MPP 生成写成新流程总延迟。
- 实测峰值 PyTorch allocated：外部 8B 约 17.36GiB；MPP full 15.25GiB、
  evidence 16.03GiB。这不是 nvidia-smi 的全部显存，也不是训练显存。

当前方案增加了外部模型计算和准备成本，同时完整开发集准确率下降，没有形成
可以作为主方案推广的质量／成本收益。

## 7. 可以得出什么，暂时不能得出什么

已得到的结论：

1. 外部 8B 的多轮请求、原像素裁剪回传、证据选择、MPP 接入和评分流程已实际跑通。
2. 当前策略给冻结 MPP 追加局部图像，整体和两个数据来源都退化；负向结果主要
   出现在成功追加图像的题，而不是失败回退组。
3. 291 个修复说明某些题可以受益，但现有自动选择没有控制住更多的退化。
4. 人工 28 题的 ROI 诊断收益不能外推为自动策略或全开发集收益。

尚不能确定主因是“8B 找错目标”还是“MPP 不会使用正确的附加视图”。两者可能
并存：外部选区尚无人审金标，且 MPP 原先适配的是五张全图，新输入改变了视觉
token 数、视图位置及提示；稀疏局部图也可能使目标关系或动作判断发生偏移。
Action 比 Scenery 下降更大与时序／关系受扰的假设相容，但不是因果证明。

旧检测＋规则 ROI 的 53.52% 与本轮 55.95% 是两个不同视图计划、覆盖、数量预算
和回放的观测值。不能把相差约 2.43 个百分点归为纯粹“换 8B 搜证”的独立收益。
旧 full 60.30%、本轮 full 60.39%、更早 CE dev 60.46% 也保留各自来源，不能替换
为一个统一数字。此前 CE 官方 55.4% 不是本轮证据策略的官方结果。

## 8. 下一步建议与停止条件

本轮先保留原五帧模型，不推进当前策略的官方 500，也不据此直接开始大规模
区域 SFT、OPD 或 RL。现阶段尚未建立可靠的自动证据收益。

如果继续局部观察方向，下一步只做能够区分原因的有限诊断：

1. 从本轮 selected 的退化／修复案例中固定抽样，核对原问题、原五帧、实际返回
   和最终选择的裁剪、两组答案。关注是否找错对象、缺关系上下文、跨帧不是同一目标，
   以及正确证据是否仍被 MPP 误用。不能仅看外部模型的 `purpose` 就认定找到证据。
2. 复用本轮视图计划和缓存，给 MPP 增加相同槽位、提示和 token 数的全图副本对照，
   与真实裁剪对比。它用于分开附加视图形式的代价和裁剪内容的影响，不需要重跑
   8B 搜索，也不涉及外部模型直接回答任务。旧规则的 duplicate 不能代替本轮对照。
3. 对没有追加裁剪但答案发生变化的控制题，核验相同输入回放的一致性，避免将
   很小的分数波动误当作新能力。

若视觉审核显示多数选区不可靠，先修正搜索／筛选；若选区正确而 MPP 仍不会使用，
才有依据在**训练集独立构造相同输入**、用原 QA 做受控 SFT 适配。开发集的修复／
退化标签只能用于诊断，不能用于逐题决定部署时是否追加图像或直接加入训练。
OPD 也要先证明教师条件的可靠优势，当前结果不提供这种依据。

若有限诊断仍未找到可复现的正向条件，应停止该自动追加区域分支，保留已完成的
全量 SFT 和原五帧 QA 基线作为项目交付基础，避免用更多训练掩盖未定位的问题。
本次仅记录建议，未启动上述诊断或新训练。
