with-VGGT official Train2000：手动逐阶段评测命令
============================================================

用途
------------------------------------------------------------

从现在开始不再运行P10--P17自动流水线。每一节都是独立命令：

  P10：只验证已经冻结的CFG calibration，不重跑。
  P11：Dev[16:64] VSS评测，GPU 0、3。
  P12：验证P11 aggregate。
  P13：构建Dev64 with-VGGT SLat sidecar，GPU 0、3。
  P14：验证sidecar。
  P15a：先跑SLat step15K，Dev48 predicted-support only，GPU 0、3。
  P16a：验证step15K aggregate。
  P15b：再跑SLat step10K，Dev48 predicted-support only，GPU 0、3。
  P16b：验证step10K aggregate。
  P17：CPU汇总10K/15K结果。

不会评测Train64，也不会把GT support作为SLat输入。official GT mesh只作为
Chamfer/F-score/Normal等指标的目标。

旧的中断P11：

  dev48_VSS_step2000_seed424344_2gpu03_hold_v2

永久保留，不删除、不续写。新P11使用独立`manual_v3`输出。

所有启动命令通过tmux后台运行并立即返回。一个阶段完成并通过随后验证后，才手动
运行下一阶段。不要再运行：

  run_source_posttrain_2gpu03.sh
  run_source_posttrain_p10_p17_eval_pipeline.sh

P15a：先启动SLat step15K Dev48 predicted-support（GPU 0、3）
============================================================

只有P12_RC=0且P14_RC=0后运行。15K作为第一条完整端点评测，生成后续10K
可严格复用的checkpoint-independent VSS coords和target mesh。该阶段支持同路径resume。

注意：`manual_v3`在旧endpoint-v1合同下失败。旧合同错误地要求raw official
SLat support与SS decoder-projected flow-target support逐坐标完全相同；Dev64实测
62/64完全相同，另外2个对象的IoU分别为0.9999020472和0.9995129757，且与冻结
SS round-trip audit精确一致。该失败输出永久保留，不恢复、不覆盖。以下`manual_v4`
使用endpoint-v2：共同上游official LH-SLat SHA256必须完全一致，实测round-trip
IoU必须匹配冻结audit，最终metric target仍严格保留SLat侧raw official target。

若`manual_v4`已经启动但希望复用失败`manual_v3`中完成的VSS坐标，先运行下面
这段。它只停止当前P15a，逐文件验证并hard-link缺失的SS coordinate pair；不会
复用旧report/run_identity/Mesh/SLat结果。随后重新运行本节P15a原命令即可resume。

  cd /home/zjr/Tracker
  set +e
  (
    set -euo pipefail
    ROOT=/data/zjr/proobjaverse_official_slat_train2000_20260813_v1
    V3=${ROOT}/eval_with_vggt_VSS2000_Vstep15000_predicted_support_seed424344_2gpu03_manual_v3/dev48_predicted
    V4=${ROOT}/eval_with_vggt_VSS2000_Vstep15000_predicted_support_seed424344_2gpu03_manual_v4/dev48_predicted
    PY=/home/zjr/anaconda3/envs/reconviagen/bin/python

    tmux kill-session -t vggt_p15a_manual 2>/dev/null || true
    sleep 5
    mapfile -t LEFT < <(pgrep -f '[e]valuate_ss_slat.*manual_v4/dev48_predicted' || true)
    if ((${#LEFT[@]})); then
      kill -TERM "${LEFT[@]}"
      sleep 5
    fi
    ! pgrep -af '[e]valuate_ss_slat.*manual_v4/dev48_predicted'

    for SHARD in shard0_16_40 shard1_40_64; do
      "${PY}" -m official_ss_with_vggt_perf_v1.reuse_partial_endpoint_ss_coords \
        --source_worker "${V3}/${SHARD}" \
        --target_worker "${V4}/${SHARD}"
    done
  )
  PARTIAL_REUSE_RC=$?
  echo "PARTIAL_REUSE_RC=${PARTIAL_REUSE_RC} (0=验证及复用PASS；然后重跑P15a)"

  cd /home/zjr/Tracker
  set +e
  (
    set -euo pipefail
    SS=/data/zjr/proobjaverse_official_native_ss_train2000_with_vggt_20260817_v1
    SLAT=/data/zjr/proobjaverse_official_slat_train2000_20260813_v1
    OUT=${SLAT}/eval_with_vggt_VSS2000_Vstep15000_predicted_support_seed424344_2gpu03_manual_v4
    LOG=${SLAT}/logs/P15a_Vstep15000_Dev48_predicted_2gpu03_manual_v4.log

    test -s "${SS}/dev48_VSS_step2000_seed424344_2gpu03_manual_v3/aggregate_v1/report.json"
