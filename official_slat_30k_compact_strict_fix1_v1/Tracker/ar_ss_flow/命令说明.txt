AR SS Flow Pose Lifting 命令说明
日期：2026-07-14

当前模型结构
============

部署可用输入：

  multi-view image + mask + K/T + sparse AR/COLMAP points

P1 离线缓存分成两条视觉路径：

  路径 A（stock）：
    原 ReconViaGen alpha crop/recenter
      -> frozen VGGT + DINO/Image encoder
      -> frozen sparse_structure_vggt_cond
      -> stock_condition [1,4096,1024]

  路径 B（geometry lifting）：
    原始 512x512 full-frame masked image，不裁剪
      -> resize 518x518，同时把 K 缩放到 518 坐标系
      -> frozen VGGT patch + frozen DINO patch
      -> visual_patch_features [V,1369,3072]
      -> frozen VGGT depth/depth confidence

  sparse points + correct K/T：
    投影 sparse point，比较 z_camera 与 VGGT depth
      -> robust scale-only fit
      -> robust affine fit
      -> 选择正 scale 且 residual 更合理的模型

  深度标定失败：
    显式 depth_consistency_enabled=false
    只使用 mask + visibility/visual-hull 权重
    禁止默认 depth scale

P2/P3 运行时 lifting：

  同一份 visual_patch_features/depth/mask
    + correct pose
    + small pose perturbation
    + shuffled pose（相机在 view 间 roll，visual view 顺序不变）
    + depth corruption（同一 depth 做固定二维 shift/水平翻转，并施加确定性 per-view scale）
      -> 分别重建 16^3 dense visual volume

  correct projection geometry 可用 FP32 缓存加速；corruption 必须重算 K/T sampling grid。
  correct volume 不是唯一缓存表示。

P3 SS Flow adapter：

  frozen stock SS Flow：
    (x_t, t, stock_condition) -> stock_velocity [B,8,16,16,16]

  trainable local adapter（无 global attention）：
    h_i = projection([x_t_i, stock_velocity_i, t])
    v_i = projection(lifted_visual_i)
    m_i = projection(support/depth/prior/XYZ metadata_i)

    interaction_i = concat(
      h_i,
      v_i,
      h_i * v_i,
      abs(h_i - v_i),
      m_i
    )

    interaction_i -> pointwise 1x1x1 MLP -> zero-init velocity delta_i
    output_i = stock_velocity_i + weighted_support_i * delta_i

  空间范围：同一个 16^3 voxel；没有 4096x4096 cross-attention。
  physical_present=false 或 null volume 时 hard bypass，velocity bit-exact stock。
  第一版不训练 VGGT、DINO、bridge、stock SS Flow、decoder、SLAT，也不开 Flow LoRA。

配对训练：

  correct/corruption 共用同一 target、noise、x_t、t、stock condition 和 visual patches。

  L = correct flow matching
    + corrupted pose/depth -> stock velocity
    + correct relative gain hinge
    + correct-vs-corruption rank hinge
    + delta norm

阶段门：

  P0/P1 cache audit PASS
    -> P2 full overfit64 input separability PASS
    -> P3 one-sample s5 finite/checkpoint PASS
    -> P4 overfit16 三个训练 seed PASS
    -> fresh P5 overfit64
    -> object-disjoint validation

任一阶段 FAIL 都停下分析，不直接增加训练步数或启用 Flow LoRA。

1. P1：构建 overfit64 可复用 lifting cache
==========================================

说明：
  约 46.5 MiB/sample，64 samples 约 3 GiB。
  ReconViaGen pipeline 会删除 depth_head；脚本会显式重新加载
  Stable-X/vggt-object-v0-1 的完整 VGGT，并只保留 aggregator/depth head。
  log 写在 cache 目录外，避免输出目录非空导致 builder 拒绝启动。

(
set -uo pipefail
cd /home/zjr/Tracker

DATA_ROOT=/data/reconvggt_pointpose_v9_ssfixed_odsplit_20260712
CACHE=/data/ar_ss_flow_pose_lifting_overfit64_v1_20260714
LOG=${CACHE}.build.log

if [ -e "${CACHE}" ]; then
  echo "output already exists: ${CACHE}"
  exit 98
fi

CUDA_VISIBLE_DEVICES=1 \
HF_HUB_OFFLINE=1 \
TRANSFORMERS_OFFLINE=1 \
ATTN_BACKEND=flash_attn \
SPCONV_ALGO=native \
MPLCONFIGDIR=/tmp/matplotlib \
NUMBA_CACHE_DIR=/tmp/numba_cache \
TORCH_EXTENSIONS_DIR=/tmp/torch_extensions \
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
/home/zjr/anaconda3/envs/reconviagen/bin/python -u \
  ar_ss_flow/build_pose_lifting_cache.py \
  --source_cache_manifest "${DATA_ROOT}/cache/train/overfit64.json" \
  --output_dir "${CACHE}" \
  --pretrained Stable-X/trellis-vggt-v0-2 \
  --vggt_pretrained Stable-X/vggt-object-v0-1 \
  --indices all \
  --max_samples 0 \
  --device cuda \
  --image_resolution 518 \
  --vggt_feature_index -1 \
  --min_depth_matches 8 \
  --affine_improvement_ratio 0.90 \
  --save_correct_geometry \
  --log_every 1 \
  2>&1 | tee "${LOG}"

CODE=${PIPESTATUS[0]}
echo "${CODE}" > "${CACHE}.P1.exit_code"
echo "P1 build exit code: ${CODE}"
exit "${CODE}"
) || true


2. P0/P1：缓存、深度标定与 correct geometry 审计
================================================

说明：
  depth calibration coverage 是数据指标，不应通过默认 scale 补齐。
  correct cached geometry 与运行时 FP32 重算必须接近数值等价。
  先看 report.json；passed=false 时不要进入训练。

(
set -uo pipefail
cd /home/zjr/Tracker

CACHE=/data/ar_ss_flow_pose_lifting_overfit64_v1_20260714
OUT=${CACHE}/independent_audit_v2

CUDA_VISIBLE_DEVICES=1 \
/home/zjr/anaconda3/envs/reconviagen/bin/python -u \
  ar_ss_flow/audit_pose_lifting_cache.py \
  --cache_manifest "${CACHE}/manifest.json" \
  --output_dir "${OUT}" \
  --indices all \
  --max_samples 0 \
  --device cuda \
  --min_depth_enabled_ratio 0.80 \
  --max_cached_geometry_diff 1.0e-5 \
  --max_roundtrip_error 1.0e-4 \
  --fail_on_error \
  2>&1 | tee "${OUT}.log"

CODE=${PIPESTATUS[0]}
echo "${CODE}" > "${OUT}.P0.exit_code"
echo "P0/P1 audit exit code: ${CODE}"
exit "${CODE}"
) || true

说明（2026-07-20 D3 v2修复）：

  cache builder在CPU上生成correct_geometry。v2固定在CPU上重建fresh geometry，
  直接检查image_grid、patch_grid、camera_depth的shape/dtype/finite/max-abs，
  并要求valid bit-exact。随后将cached CPU geometry和fresh CPU geometry分别送入
  指定的runtime device重放volume/metadata。因此1e-5现在是同源几何重放硬门，
  不再用来覆盖CPU/CUDA投影坐标差异。projection round-trip仍保留1e-4独立硬门。

  旧v1在CUDA上重建fresh geometry，将约2.38e-7的CPU/CUDA grid差异经
  grid_sample和1e-6 support硬阈值放大，产生了数值审计假失败。旧报告仅作历史证据，
  不应通过放宽到4e-3来准入。

  必须加--fail_on_error。外层`|| true`只保护交互终端，真实状态读取
  `${OUT}.P0.exit_code`和report.json中的passed，不能只看shell最终返回值。

  paired_same_visual_features=true
  null_is_exact_zero=true
  三类 corruption 的 sample_pass_ratio >= 0.80

  null_is_exact_zero = true

因为它会减少有效view/权重，使raw weighted variance表面上更低。该指标没有固定两路的
active-view集合，不能作为correct pose是否更合理的可靠硬门。C3改用actual corruption、
same-voxel pair features、constant/spatial controls和最终Flow/rollout结果直接判定。

12. C3：State-conditioned Same-voxel Pair-feature SS Adapter（2026-07-15）
============================================================================

12.0 当前模型结构、实验边界与判定层级
--------------------------------------

本节是跨视图 correspondence 路线的最后一轮结构性验证。它修复 C2 的两个关键问题：

  1. 不再把 C1 confidence 只压成归一化 view weight 或 object scalar gate；
  2. correct、pose corruption、cross-object corruption 都重建自己的真实 pair evidence，
     不再对同一个 correct volume 只替换标量 gate。

结构：

  frozen C1 pairwise correspondence model
    + 同一 16^3 voxel 内的 view-pair features：
        projected pair embeddings
        abs difference / product
        pair confidence logit/probability
        depth residual difference
        support / ray cosine / camera-depth difference
    -> [B, pair_count, pair_feature_dim, 16,16,16]

  frozen stock SS Flow：
    (x_t, t, stock_condition) -> stock_velocity

  trainable C3 local adapter（约 0.51M 参数）：
    query = projection(x_t, stock_velocity, t/1000)
    key/value = 当前 voxel 的 view-pair features
    + lifted visual volume
    + support/depth/prior/XYZ metadata
    -> pointwise fusion
    -> zero-init velocity residual

  output = stock_velocity
         + physical_scale * support_gate * time_gate * residual

明确约束：

  无 4096x4096 global attention；
  只在同一个 16^3 voxel 内查询 view pairs；
  physical_present=false -> bit-exact stock；
  null evidence -> bit-exact stock；
  t<=0.5 -> bit-exact stock；
  VGGT/DINO/bridge/stock SS Flow/decoder/SLAT/C1 全部冻结；
  第一版不开 Flow LoRA。

配对训练：

  correct 与 wrong 共用 target、noise、x_t、t、stock condition；
  wrong 是实际重建的 cyclic/reverse/cross-object evidence；
  correct -> target velocity；
  wrong -> stock velocity；
  同时约束 correct 优于 stock、correct 优于 wrong、delta norm。

重要边界：

  当前 cache 仍是已知 canonical frame 的合成机制数据。
  C3 PASS 只能证明“该局部跨视图机制值得继续”；不能替代 P0.5 的真实 AR
  object-frame/Sim(3) 恢复问题，也不能直接声称真实 AR 部署收益。

判定分两层：

  benchmark_relaxed：
    只判断 teacher-forced correct 是否稳定优于 frozen ReconViaGen stock；
    用于决定是否值得跑昂贵 rollout；不能证明 pose-specific causality。

  mechanism_strict：
    还要求 correct 优于 constant-pair、spatial-permuted-pair 和所有 actual corruption；
    只有这一层通过，才能把收益归因于正确 pose/view correspondence。

12.8 标准能否放宽，以及允许的结论
------------------------------------

可以放宽“是否值得继续”的准入门，但不能放宽“pose机制成立”的归因门。

A. 工程门，不可放宽：

  finite checkpoint；
  optimizer/scaler finite；
  stock Flow 和 C1 冻结；
  off/null/inactive-t bit-exact stock；
  三 seed 协议完全一致；
  train/eval object 不重叠。

B. ReconViaGen 内部基线收益门，可作为探索性放宽标准：

  三个训练 seed 的 teacher-forced correct gain mean/median > 0；
  object-balanced correct > stock win rate >= 55%；
  五个 active t 至少 3 个为正；
  随后 decoded rollout 的 IoU mean/median > 0、object win >= 55%；
  precision 平均下降不超过 1e-4；
  largest-component ratio 平均下降不超过 0.01。

通过 B、但未通过 C 时，只允许写：

  “C3 在注册的 object-disjoint、same-noise 协议上优于 frozen ReconViaGen baseline。”

不能写：

  “模型学会了正确 pose correspondence”或“收益由 Point/Pose 对齐导致”。

C. Pose/correspondence 机制门，不应放宽：

  object-balanced correct > stock win rate >= 65%；
  correct > constant-pair 与 spatial-permuted-pair；
  correct > actual cyclic/reverse/cross-object evidence；
  五个 active t 至少 4 个方向为正；
  wrong branches 近 stock；
  三个训练 seed 均通过。

D. 与 TRELLIS / Pixal3D 的外部模型比较：

  不能比较 SS Flow MSE，因为不同模型的 latent、target 和 flow parameterization 不同。
  必须统一：

    object-disjoint test objects
    输入 image/view 数和分辨率
    pose/mask/point 可见信息预算
    sampling seed 数和 sampling compute
    canonical normalization

  比较最终输出：

    occupancy IoU / precision / recall
    Chamfer / F-score（有 mesh/point GT 时）
    multi-view silhouette/depth reprojection
    component count / largest-component ratio
    每对象 win rate及 bootstrap confidence interval

  对 ReconViaGen 的比较最直接：本脚本已在同一 stock condition、同一 noise 下配对。
  对原 TRELLIS 或 Pixal3D，必须另行生成同一 test manifest 的最终 decoded geometry，
  再按上述公共指标比较；不得用本脚本的 teacher-forced Flow gain 声称跨模型领先。

停止条件：

  三 seed benchmark_relaxed 失败：停止 C3，不跑 rollout；
  benchmark_relaxed 通过但 rollout 失败：停止增加训练步数，收益未到最终生成；
  rollout 优于 stock 但 mechanism_strict 失败：可保留 baseline-improvement 结果，
    但将模块解释为 learned local regularizer，不宣称 pose-specific；
  mechanism_strict 与 rollout 都通过：才进入 fresh overfit64/validation 和真实 AR frame 数据。
