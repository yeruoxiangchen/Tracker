# Mixed10k 数据构建思路与当前进度

日期：2026-07-29

## 1. 当前目标

第一阶段目标是冻结一个 10k object-disjoint 数据集：

```text
Objaverse: 6000 objects
OmniObject3D: 4000 objects
train/val/test: 9000/500/500 objects
每个来源对象尝试2条AR轨迹
最终每个对象最多保留1条8-view sequence
```

该阶段解决的是训练样本数量、形状覆盖和 AR 风格有限视角观测构造，不直接证明
Direct-SLAT Full 优于 Stock，也不等于已经开始 10k 模型长训。

## 2. 两个来源的实际作用

Objaverse 提供大规模互联网 3D 资产。已下载约 30k GLB，并根据 256-object pilot 的
有效产出率冻结 11546 个候选，以支持最终筛出 6000 个对象。

OmniObject3D 当前使用的是 215 个类别包中的扫描 Mesh，而不是数据集配套真实照片。
它增加了扫描几何、材质和对象类别分布，但最终输入图像仍由 Blender 合成。因此当前
10k 是“两个不同 Mesh 来源上的合成 AR 观测”，不是合成图像与真实相机图像的混合。

真实相机数据应在合成训练链路稳定后作为独立阶段加入。没有可靠 GT Mesh 的真实序列
更适合用于域适配、一致性损失和人工/无参考评估；具有扫描 Mesh、相机标定和可对齐
图像的数据才能进入严格 Mesh 监督。若真实数据已经给出世界坐标相机和配准 Mesh，
不应再次估计 TM2W；若只有局部点云与相机轨迹，则仍需冻结并审计点云/物体到世界坐标
变换。

## 3. 每个对象构建什么

当前构建器对每个 Mesh 执行：

1. 用 trimesh 读取场景并冻结源文件身份；
2. 以 AABB 中心和平移尺度规范化到 canonical latent frame；
3. 采样 160k surface points，在 64³ 网格生成稀疏结构与 SS latent；
4. 把 canonical 点旋转到 Pixal3D render frame；
5. 随机产生 AR 风格有限环绕轨迹；
6. 生成 24 个候选视角，再按 mask、构图与 pose 多样性选择 8 帧；
7. 使用 Blender Cycles/CUDA 生成 512×512 RGBA、mask、内参和 c2w；
8. 检查投影支持、前景比例、边界裁切、纹理、几何体素数和 frame selection；
9. 保存训练所需的图像、mask、相机、稀疏坐标、latent 和审计字段。

8 帧是最终输入预算，24 帧只是轨迹候选池，不会全部进入模型。

## 4. 为什么需要多级 gate

大规模 Mesh 来源同时包含正常的难样本和基础设施错误，两者必须分开：

```text
正常数据筛选:
  frame_selection_rejected
  projection_rejected
  appearance_rejected
  geometry_rejected
  source_asset_rejected（真实坏资产）

基础设施失败:
  renderer_failed
  manifest/inventory不闭合
  代码或依赖崩溃
  source frame 与 Blender frame 不一致
```

单个真实坏资产可以有界跳过，但系统性坐标错误不能通过放宽阈值或批量跳过来掩盖。
因此流水线顺序冻结为：

```text
source freeze
  -> 无图像 source-frame audit
  -> 两来源4-object render smoke
  -> 两来源16-object render smoke
  -> Omni 256-object pilot
  -> 候选预算门
  -> 正式24分片渲染
  -> 低纹理配额与object-disjoint 10k finalization
  -> 最终数据完整性/质量复算
```

## 7. Omni v3 失败及根因

同一 R3 的 Omni shard_000：

```text
sequence tasks = 32
accepted = 0
source_asset_rejected = 32
耗时约2小时27分钟
```

这不是 32 个独立坏资产，而是 OBJ source frame 的系统性代码错误。Blender 3 OBJ
importer 默认已经执行：

```text
[x, y, z] -> [x, -z, y]
```

旧 OBJ 归一化分支随后又应用一次 `PIXAL3D_ROTATION_4X4`，并在错误 frame 中减去
trimesh center，造成 Y/Z 互换和非零中心。典型误差：

```text
omni_anise_013:   max_abs约0.096
omni_anise_025:   max_abs约0.375
omni_antique_017: max_abs约0.342
tolerance:        0.001
```

旧 v3 Omni pilot 的前几个任务也全部复现相同错误，因此 v3 输出应保留为失败现场，
不可续跑或改写。

因此 S5 表示“没有灾难性 Mesh 退化，但最终效益未建立”。可以继续 897-object 的
S6 step100→400，用来检验训练量是否能把 S4 teacher 优势传到 rollout/decoder；
S6 后必须执行 S7。当前结果不能批准 10k 模型长训。

数据构建和模型训练可有限并行：

```text
Direct-SLAT S6: 2 GPUs
Mixed10k smoke/pilot: <=2 GPUs
项目合计: <=4 GPUs
```

10k 数据本身可以继续构建和冻结，因为它是后续实验基础设施；训练扩量仍按：

```text
897-object最终Mesh稳定正向
  -> 1k短训
  -> 3k scaling
  -> 10k长训
```

若 step400 仍只有 teacher 正向而 Mesh 中性或负向，应停止同结构扩步，优先修改
rollout/decoder 对齐，而不是用更大数据掩盖机制未迁移。
