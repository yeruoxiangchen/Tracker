使用约定
--------

1. 每个编号下的圆括号块都是一条独立命令，逐块复制到终端执行。
2. D8.0--D8.6 都是短 CPU/IO 命令，直接在当前终端打印，不需要监视。
3. D8.2 后只需人工填写 255 行 semantic_subject_label；`1`表示接受、`0`表示拒绝，
   也兼容正式英文标签。rejection_reason 可留空，reviewer 由 D8.4 统一补齐。
4. D9/D10 是长 GPU cache 任务，使用 user service；启动命令和监视命令分开。
5. 任一步非零即停止，不要跳过。所有正式输出都是新不可变目录。
6. 576 是 sequence 数；当前对象级事实是 288 attempted、255 至少一条 accepted。

(
  set -euo pipefail
  cd /home/zjr/Tracker
  PY=/home/zjr/anaconda3/envs/reconviagen/bin/python

  "${PY}" -m py_compile \
    pose_point_depth_mv/dataset_tools/prepare_objaverse_semantic_review.py \

  "${PY}" - <<'PY'
import json
from pathlib import Path
from collections import Counter, defaultdict

from pose_point_depth_mv.dataset_tools.freeze_reviewed_mixed1k_dataset import (
    completed_render_manifests,
    load_manifest,
    object_uid,
)

root = Path('/data/zjr/dataset10k_20260726/gap_objaverse288_cyclescuda_v1')
manifests, markers = completed_render_manifests(
    root, source='objaverse', expected_shards=16
)
counts = defaultdict(lambda: {'accepted': 0, 'failed': 0})
failure_counts = Counter()
accepted_sequences = 0
failed_sequences = 0
for path in manifests:
    payload = load_manifest(path)
    for row in payload['samples']:
        counts[object_uid(row)]['accepted'] += 1
        accepted_sequences += 1
    for row in payload.get('failures', []):
        counts[object_uid(row)]['failed'] += 1
        failed_sequences += 1
        failure_counts[str(row.get('reason', row.get('failure_class', 'unknown')))] += 1

summary = {
    'completed_markers': len(markers),
    'attempted_sequences': accepted_sequences + failed_sequences,
    'accepted_sequences': accepted_sequences,
    'failed_sequences': failed_sequences,
    'attempted_objects': len(counts),
    'objects_with_accepted_sequence': sum(v['accepted'] > 0 for v in counts.values()),
    'objects_with_two_accepted': sum(v['accepted'] == 2 for v in counts.values()),
    'objects_with_one_accepted': sum(v['accepted'] == 1 for v in counts.values()),
    'objects_with_zero_accepted': sum(v['accepted'] == 0 for v in counts.values()),
    'failure_counts': dict(sorted(failure_counts.items())),
}
print(json.dumps(summary, indent=2, ensure_ascii=False))
expected = {
    'completed_markers': 16,
    'attempted_sequences': 576,
    'accepted_sequences': 484,
    'failed_sequences': 92,
    'attempted_objects': 288,
    'objects_with_accepted_sequence': 255,
    'objects_with_two_accepted': 229,
    'objects_with_one_accepted': 26,
    'objects_with_zero_accepted': 33,
}
for key, value in expected.items():
    assert summary[key] == value, (key, summary[key], value)
print('D8.0 PASS: all 16 markers are hash-bound; object-level inventory is exact')
PY
)

D9 输入cache修订说明
=====================

旧 v1 命令曾将 reviewed split manifest 直接传给 pose-lifting builder，跳过了
point prior 和 14 维 PointPose physical cache，因此在真正 GPU 计算前报
`physical feature schema mismatch: cache=()`。D9 v2 又绑定了未完成对象级SS repair的
raw freeze。保留 v1/v2 目录和日志，最终修正链路全部
写入：

  /data/zjr/native3d_condition_reviewed1k_inputs_20260730_v3

正确顺序是：

  raw reviewed split -> object-level SS repair -> point prior
  -> PointPose physical cache -> pose lifting
