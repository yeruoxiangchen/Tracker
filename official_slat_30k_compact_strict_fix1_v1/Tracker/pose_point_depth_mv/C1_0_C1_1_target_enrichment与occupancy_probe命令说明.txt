C1.0/C1.1 v2 target enrichment 与 nested occupancy probe 命令说明
日期：2026-07-19

======================================================================
一、当前模型和实验边界
======================================================================

C0.3/N3已经验证的输入：

  view-identity visual + pose/depth evidence
    -> symmetric gaussian3 neighborhood lifting
    -> per-voxel correct-vs-hardest-corruption margin
    -> hard_admitted_soft_weight（正式）
    -> continuous_soft_weight（消融）

本阶段新增：

  C1.0（不训练）：
    C0 map与SS target_coords按UID连接；
    target_coords_64 // 4得到exact 16^3 occupancy；
    3x3x3 target neighborhood只作辅助报告；
    比较hard binary、hard-admitted、continuous、active-only、
    reliability-only、固定active内的空间置换，以及由真实
    pose/depth/visual corrupted voxel score重建的corruption map。
    正式hardest-corruption使用pose-cyclic、depth-view-cyclic、
    visual-view-cyclic三个training controls，与N3的四分支集合一致；
    pose-reverse和depth-spatial只作held-out诊断。

    target坐标协议：
      target_coords最后三维为[x,y,z]；
      16^3 flatten顺序为x*16*16+y*16+z；
      每个真实cache样本执行64^3 -> 16^3 -> canonical center round-trip；
      报告保存exact和surface-r1 target mask SHA-256，跨seed必须完全一致。

    Average Precision使用tie-aware threshold grouping，但只作诊断，
    不再进入正式PASS/FAIL。

  C1.1（仅C1.0多seed PASS后训练）：
    在完全相同的对象、标签、初始化seed、Adam、学习率、步数和
    object-balanced BCE下，独立训练三个嵌套模型：

      M0: logit[x] = bias

      M1: logit[x] = bias
                     + softplus(w_reliability) * reliability[x]

      M2: logit[x] = bias
                     + softplus(w_score) * c1_weight[x]
                     + softplus(w_reliability) * reliability[x]

    M1是独立训练的reliability-only最优基线，不再是将M2的score置零。
    M2还在同一calibrator下测试pose/depth/visual corruption map和
    fixed-active spatial permutation。

    不使用XYZ；
    不使用卷积或邻域网络；
    不读取Flow state；
    不加载VGGT、bridge、SS Flow或decoder；
    target occupancy只作为BCE标签，不进入map、gate或输入特征。

本阶段仍禁止：

  Flow LoRA
  decoder微调
  SS Flow residual
  target/mesh信息进入模型输入

科学硬门：

  C1.0候选权重必须在fresh48和untouched holdout、三个训练seed上，
  同时优于active-only、reliability-only、空间置换和最强真实
  corruption-derived control；
  mean/median > 0，object win >= 65%，bootstrap CI lower > 0。
  同一admitted policy也必须在三个seed的train16上通过，否则
  C1.1没有合法的训练输入绑定。

  C1.1必须在fresh48和holdout上同时满足：
    M2 > 独立训练的M1；
    M2 > spatial-permuted M2；
    M2 > 最强corruption-derived M2；
    2-view组在上述三类对照上的mean均不得为负。
  任何FAIL都停在当前阶段，不启用Flow LoRA。

======================================================================
二、命令运行约定
======================================================================

下面两个runner都在前台运行并持续打印进度：

  不使用nohup；
  不放入后台；
  不启动专门监视进程；
  每阶段写*.exit_code；
  科学FAIL写入report.json，但runner自身返回0；
  runner由/bin/bash子进程执行，不会关闭当前交互终端。

若某个输出目录存在但report.json不完整，runner返回该阶段code=98，
不会自动删除或覆盖目录。人工确认后改名该目录，再重跑即可。
