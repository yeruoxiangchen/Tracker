ProObjaverse 官方 Native-SS 对 strict ReconViaGen Stock-SS：纯 Support 比较
================================================================================

本测试只运行：

  strict 路线：冻结 RGBA 8视图 -> VGGT -> Stock SS -> 64^3 support
  native 路线：复用已冻结 posed-DINO -> official Native-SS step2000 EMA support

两路都相对同一个 official GT-SLat coordinate support 计算：

  IoU / Precision / Recall / F1
  support数量比、数量log误差
  component count及其相对GT误差
  largest-component ratio及其相对GT误差

不运行 SLat，不运行 Mesh decoder，不生成 Mesh。

主集合固定为未参与 Native-SS CFG 校准的 Dev[16:64)，即 held-out Dev48，
每个对象固定 seed 42/43/44；统计单位先对每个对象的三个seed取均值，再做对象bootstrap。

S2. 监视单个GPU 3后台worker
================================================================================

下面是普通bash循环，不嵌套 watch/bash -lc，避免先前的引号和重定向错误。
Ctrl-C只停止监视，不停止后台评测。

cd /home/zjr/Tracker

OUT=/data/zjr/proobjaverse_official_native_ss_vs_strict_reconviagen_ss_support_20260816_v1
UNIT=tracker-proobj-strict-rg-ss-support-gpu3-sharedrun-v2.service
WORKER_OUT=${OUT}/worker_00_of_01
LOG=${OUT}/logs/worker_00_gpu3_sharedrun_v2.log

while true; do
  date -u
  printf 'GPU3 worker service='
  systemctl --user is-active ${UNIT} 2>/dev/null || true
  printf '  completed support records / 144: '
  find ${WORKER_OUT}/records -name 'seed_*.json' -type f 2>/dev/null | wc -l
  if [ -s ${WORKER_OUT}/report.json ]; then echo '  report: COMPLETE'; fi
  tail -n 1 ${LOG} 2>/dev/null || true
  if ! systemctl --user is-active --quiet ${UNIT}; then
    if [ -s ${WORKER_OUT}/report.json ]; then
      echo 'worker finished successfully; run S3 next.'
    else
      echo 'worker stopped without report; inspect the log above.'
    fi
    break
  fi
  sleep 20
done

统计和结论边界
================================================================================

1. strict support会逐seed核对历史完整strict ReconViaGen report里的coord_count。
   历史成功记录只要有一个数量不能精确回放，worker立即失败，不生成科学结论。
   当前实现直接调用Tracker/ReconViaGen原始pipeline.run的SS-only提前返回分支；
   CPU noise、VGGT、Stock-SS condition、sampler和decoder均与完整原版共享同一路径。

2. Native support直接复用已冻结的144份ss_coords，不重新运行SLat25k；这些support与
   15k/20k/25k无关，路径只是复用已有冻结产物。

3. 两路使用同一Dev48、同一8张源视图身份、同一GT support和同一64^3坐标合同，
   但输入接口和部署采样各自保持原方法：strict使用VGGT，Native使用已知pose+DINO。
   因此这证明的是SS endpoint质量，不是“同condition、同noise的纯网络结构消融”。

4. 只有以下预设门全部通过时，
   native_ss_support_advantage_established=true：

   - 运行与坐标合同完整；
   - IoU mean/median为正；
   - IoU对象胜率>50%；
   - IoU对象bootstrap 95% CI下界>0；
   - Precision和Recall均值不退化。

5. Support通过后，才能另行运行：

   Native SS support -> 同一VGGT-conditioned Stock SLat -> Mesh

   该后续实验只裁决Stock-SLat兼容性，不回头改写本纯Support结论。
