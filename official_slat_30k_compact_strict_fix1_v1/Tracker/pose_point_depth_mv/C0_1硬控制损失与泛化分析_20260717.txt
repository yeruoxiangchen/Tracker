C0.1 fresh48 hard gate 失败后的训练目标分析
日期：2026-07-17

一、结论

提出的五项措施有明确的预期收益。其中：

1. 逐 voxel hard-control loss 和 2. all-control + smooth hard loss 是必须修正的训练目标错位；
3. confidence weighting 用于处理局部噪声和两视角歧义；
4. view-count 平衡有帮助，但不是当前失败的主因；
5. 显式 depth pair 特征是有价值的第二轮结构增强。

当前训练通过、fresh48 hard gate 失败，并不意味着跨视角空间信号不存在。fresh48 的 spatial_view_misaligned control 强烈失败：空间错配 margin 均值约 +10.98、object win rate 为 100%。这说明 head 能检测同位置跨视角空间绑定。失败发生在更细的要求：同一 voxel 必须同时胜过 pose_cyclic1、depth_view_cyclic1、visual_view_cyclic1 三种相对细微的训练 control。

二、当前训练目标和 C0.1 正式门不一致

当前训练同时前向三种 control，但：

- sample_rank / hard_rank 只作用于对象级 sample_score；
- voxel 分支只用 BCE 要求 correct voxel score 为 1、每个 control voxel score 为 0；
- 正式 C0.1 gate 却使用逐位置的 hard margin：

  hard_margin[x] = correct_score[x] - max_k(control_score_k[x])

因此训练没有直接优化 C0.1 最终用来构造 gate 的量。对应代码：

pose_point_depth_mv/train_correspondence_head.py
  254-285：对象级 rank 和逐 voxel BCE

pose_point_depth_mv/correspondence_head.py
  246-256：评估时的逐 voxel hard margin

一个直接证据是 fresh48 中对象 3e7376ae...：

  pose mean margin   = +3.92
  depth mean margin  = +1.22
  visual mean margin = +1.35
  hard voxel mean    = -1.84

三个对象级平均 margin 都为正，但不同 voxel 的最难 control 不同。逐位置取 max 后，hard margin 仍为负。这正是局部 hard-control loss 应解决的问题。

三、建议的局部 ranking loss

令：

  d_k(x) = score_correct(x) - score_control_k(x)

不建议只使用裸 max，因为 argmax control 才有梯度，最难 control 会在不同位置、不同 batch 之间切换。推荐同时训练每个 control，并附加强调最难负例的平滑项：

  L_all = mean_k softplus((margin - d_k) / temperature)

  L_hard = softplus((margin - softmin_k(d_k)) / temperature)

  L_voxel_rank = L_all + 0.5 * L_hard

其中 softmin 由 logsumexp 实现，给所有接近最难的 control 提供梯度。也可先采用更容易审计的版本：

  mean(per-control hinge) + 0.5 * hard-control hinge

旧 voxel BCE 可保留，但应降低权重，避免模型主要通过把正负 logits 推向饱和来降低损失，而没有改善相对 margin。

四、confidence weighting 的正确语义

当前 pair pooling 已经使用：

  base_weight = mask * depth confidence * depth consistency

但 voxel BCE 对全部 active voxel 等权。增加 loss weighting 有意义，尤其是 fresh48 的两视角和低支持 tail。

可靠性权重必须：

  只由 correct evidence 计算；
  detach；
  对 correct 与所有 control 完全共享；
  不读取模型 score、target 或 corruption 自己的 support。

可用：

  pair support
  * correct depth confidence
  * correct visibility agreement

作为 w[x]。不要强制所有 active voxel 都有大 margin。更合理的是只在高置信 voxel 内，额外强调 violation 最大的 30%-50%（CVaR / hard-example weighting）。低置信、单薄支持或遮挡边界位置允许 gate abstain。

五、view count 的作用

view-count balance 值得加入，但不能把当前问题简单归因于“2-view 训练太少”。train16 的原生对象分布是：

  2-view: 4 objects
  4-view: 6 objects
  8-view: 6 objects

当前训练对每个对象均匀采样，再在 2..V 间随机选择子集。估计约 43% 的训练步骤实际使用 2-view，而精确使用 8-view 的步骤约 5%。因此：

  - 2-view 并未在步骤数上被忽略；
  - 原生 2-view 对象只有 4 个，类型覆盖不足；
  - 2-view 只有一个 pair，本身没有跨 pair 冗余。

train16 上 2-view local pass rate 为 100%，fresh48 上只有 40%，说明这是明显的对象/几何分布泛化问题。后续应按“原生 view-count bucket”平衡采样，并使用 {2,4,8} 的固定子集协议，而不是随机产生 3/5/6/7-view 子集。2-view 不能删除，但应使用更保守的 reliability threshold 或允许更低覆盖的 abstention 策略。

六、depth 是否需要加强

值得加强，但不能简单认为现有模型没有 depth。当前 per-view geometry 已包含：

  valid
  mask weight
  depth confidence weight
  depth consistency weight
  absolute normalized depth residual
  combined weight
  camera ray
  camera depth
  world ray / camera origin / patch UV

其中真正缺失的是 signed depth residual。当前 residual 在构建时使用 absolute value，因此丢失了：

  voxel 在可见表面前方（free space）
  vs voxel 在表面附近
  vs voxel 在表面后方（occluded / unknown）

的方向语义。

后续可加入：

  signed_depth_residual
  abs(residual_i - residual_j)
  depth_conf_i * depth_conf_j
  surface-band agreement
  free-space conflict
  occlusion-side agreement

当前 depth_view_cyclic1 在 fresh48 的 hardest-control identity 中约占 47.9%。这表示它最常是模型最难区分的错误分支，不等同于 depth 一定是最有用的输入，但说明 depth-view identity 是最需要强化的边界。

七、不要同时修改所有变量

推荐顺序：

C0.2a：训练目标消融
  - head 和 evidence 不变；
  - 加入 all-control + smooth hard voxel rank loss；
  - 保持原始 BCE；
  - 记录每 control 的 voxel violation、hard margin、正比例和 view-count 分组。

C0.2b：可靠性与采样协议
  - 使用 correct-only detached reliability weight；
  - 按原生 2/4/8-view bucket 平衡对象；
  - 固定 {2,4,8} 子集协议；
  - 对两视角使用保守的高置信 gate / abstention。

C0.2c：深度特征消融
  - 仅当 C0.2a/b 中 depth_view_cyclic1 仍为主 hardest control 时加入 signed/pairwise depth features；
  - 不与新的 loss、采样策略同时改变，以保留因果归因。

八、实验准入与风险

直接在同一个 train16 上加入 hard loss，很可能只会让 train margin 更大。它可以作为“目标是否对齐”的机制实验，但不能作为泛化结论。

fresh48 已经被用于观察和决定下一版方案，应视为开发集。正式泛化结论应使用：

  更大的 object-disjoint training set
  + 新的未查看 holdout

或至少进行多个 object-disjoint cross-validation fold。每轮仍保持原有 C0.1 的预注册门，不降低 hard-margin、正 voxel 比例或 local object pass 的阈值。

在 C0.2 稳定通过 fresh object-disjoint gate、多 seed 和 held-out controls 之前：

  不进入 C1；
  不启用 Flow LoRA；
  不把 spatial_view_misaligned 加入训练 loss（它目前过于容易，应保留为审计控制）。
