大数据直接 Flow 训练与测试命令（2026-07-20）
================================================

一、当前模型结构
----------------

输入仍使用原 ReconViaGen 的 stock image/VGGT condition，同时增加一条位于 SS Flow
16^3 token 空间内的物理分支：

  每个 view 的 VGGT patch + DINO/Image patch
  + 真实 K/T、camera ray、VGGT depth/depth confidence、mask
  + 稀疏 AR/Colmap point prior
      -> N3 已验证的 gaussian3 correspondence/reliability 特征
      -> 保留 view identity 的 same-voxel pair fusion
      -> 3x3x3 local 3D convolution
      -> zero-init 1024-d physical token
      -> 在 SS Flow block 0 前与原 4096 个 16^3 token 相加
      -> 24 个冻结 SS Flow block + attention LoRA
      -> SS latent / frozen decoder

冻结：VGGT、DINO/Image encoder、stock get_ss_cond、N3 correspondence head、
SS Flow base、SS decoder。训练：view-identity physical encoder 和 SS Flow LoRA。

严格回退：physical_present=False 或 null evidence 时，同时关闭 physical residual 和
Flow LoRA，velocity 必须 bit-exact 等于 stock ReconViaGen。

P0-performance 训练目标：

  1. correct physical 的 Flow matching（主损失）；
  2. frozen decoder occupancy（弱辅助，weight=0.001，每 4 个 micro-step 一次）；
  3. 小权重 delta norm。

P0 不构建 corruption 分支，wrong-stock、correct-gain、rank 权重均为 0。只有 P0 在
object-disjoint 数据上优于 stock 后，才运行 P1-weak-mechanism：每步随机一个
pose/depth/visual corruption，仅增加 0.01 的弱 relative-rank 正则。corruption 的主要
职责仍是评估机制归因，不是主训练目标。

注意：两卡真实 smoke 中 raw occupancy loss 约 31.6，原 0.02 权重会压过约 0.067
的 Flow loss，因此正式命令使用 0.001。0.02 只验证过链路，不应继续用于训练。

二、代码改动
------------

  pose_point_depth_mv/direct_flow.py
    N3 绑定、显式 XYZ-volume/Flow-token 映射、schema/hash 绑定、view-identity
    pose/depth/visual/point evidence、16^3 local encoder、stock-preserving Flow LoRA。

  pose_point_depth_mv/train_direct_flow.py
    performance/weak-mechanism profile、object-balanced sampler、两卡 DDP、
    BF16/FP16 finite guard、完整 resume/checkpoint 绑定、可选 paired corruption、
    Flow + frozen-decoder occupancy 联合训练及独立输出梯度审计。

  pose_point_depth_mv/eval_direct_flow.py
    UID-first 配对且 object-balanced 的 teacher-forced 和 rollout 评估；分别报告：
      benchmark_relaxed：只要求优于 stock ReconViaGen；
      mechanism_strict：额外要求 correct 优于 pose/depth/visual corruptions。

  pose_point_depth_mv/test_direct_flow.py
  pose_point_depth_mv/test_direct_flow_statistics.py
    distinct-axis 16^3 token 顺序、null exact-zero、stock bypass、梯度、cache schema、
    object-balanced sampler、UID rollout 配对与 object-balanced 统计测试。

  pose_point_depth_mv/audit_direct_flow_admission.py
    完整 train/val cache、stock condition、N3/hash、schema 与 object-disjoint 自动准入，
    并严格绑定四份审计报告的 manifest/schema/UID hash。

  ar_ss_flow/build_pose_lifting_cache.py
    将 native stock pipeline 与替换 VGGT 的 lifting pipeline 分离；缓存 stock_condition
    必须来自未替换的 ReconViaGen VGGT，lifting 特征使用独立的 depth/VGGT pipeline。

  ar_ss_flow/audit_pose_lifting_cache.py
  ar_ss_flow/audit_cached_stock_condition.py
    审计报告保存 cache manifest、schema、配置和 UID/object hash，供 admission 绑定。

  pose_point_depth_mv/eval_direct_flow.py
    pilot rollout 放宽为明显退化门 0.01/0.01/0.02；D10.1 增加 frozen-decoder
    teacher occupancy 评估。

三、运行约定
------------

1. 每一节单独复制运行，全部前台执行并实时输出，不使用 nohup/background/PID monitor。
2. 所有 shell 段都不执行 exit；错误只记录到 *.exit_code，段末 true 保持终端开启。
3. output 已完整存在时复用；存在不完整目录时返回 98，不自动删除、不覆盖。
4. 先完成 D0-D10。只有 D10 的 object-disjoint 结果满足放宽门，才运行 D11-D13。
5. 放宽门只支持“优于 stock ReconViaGen”的结论。与 TRELLIS/Pixal3D 的正式比较仍需
   在相同输入、相同 split、相同最终 3D 指标下另行评估。

固定 N3 依赖：

  N3_REPORT=pose_point_depth_mv/outputs/c0_3_gaussian3_s200_multiseed_holdout_summary_20260718/report.json
  CORR_CKPT=pose_point_depth_mv/outputs/c0_3_gaussian3_train16_s200_seed42_bf16_20260718/checkpoints/last.pt
