ProObjaverse 官方 SLat condition+LoRA：Train2000 四卡 8000-step 后台分段训练测试命令
====================================================================================

使用方法
--------

- 本文档用于逐段复制命令，不要直接 `bash` 整个 txt。
- 训练固定使用物理 GPU `1,2,3,4`。
- 四卡 DDP：4 GPU × grad_accum 2 = global effective batch 8。
- 冻结协议池共 2128 对：train=2000、dev=64、predicted-support bridge=32、
  decoder audit=32。四组对象互斥。
- 主模型固定为 P7 选中的 `condition_lora`：posed-DINO every-block condition
  + rank-8 SLat attention LoRA，architecture=v2。
- 使用官方 SLat target 和 GT support；本轮不运行 Native SS predicted support。
- 从精确 Stock 初始化新轨迹，不从 P7 Train16 checkpoint 初始化。
- `max_steps` 从第一次启动开始永久固定为 8000；`run_until_step` 依次使用
  2000、4000、8000。续训必须恢复相同目录中的 checkpoint、optimizer、EMA 和 RNG。
- 网络、uniform timestep、velocity-MSE、学习率和采样合同均保持 P7 配方；
  不同时加入 decoder loss、trust region、rollout 或低噪声课程。

预计纯训练时间：四卡约 10.4 小时，建议预留 11--12 小时；缓存和 Mesh 评测另计。

L11. 判读规则
=============

1. Train16、Train64、Dev64 都相对 Stock 为正：
   当前官方-target condition+LoRA 路线同时具备拟合和初步泛化，可另行冻结
   checkpoint 后再建立 predicted-support bridge 实验。

2. Train16 为正、Train64 为负：
   只能记忆高曝光小集合；先看 2000 -> 4000 -> 8000 的 Train64 曲线，不能
   用 Train16 结果声称整体训练分布已拟合。

3. Train64 为正、Dev64 为负：
   属于普通泛化不足或过拟合；可以选更早 checkpoint，而不是继续增加步数。

4. 到 step8000 连 Train64 的 Chamfer/F-score 都没有超过 Stock：
   停止单纯堆步数，再检查 timestep 分桶、Stock trust region 和 decoder-aware
   几何目标。

5. LCR 必须结合对象级异常检查。P7 中 LoRA 的 Chamfer/Normal 增量可靠，但
   LCR 有明显长尾；不能把 Chamfer 改善直接写成拓扑全面改善。

6. 本文档所有评测均为 `formal=false`。Dev64 是开发选择集；最终科学结论仍需
   在架构和 checkpoint 完全冻结后使用另一份未参与开发的协议。

7. 当前严禁消费 `predicted_support_bridge32`。只有 object-disjoint Dev64 的
   GT-support 门通过后，才单独建立 Native SS predicted-support 损失评测。
