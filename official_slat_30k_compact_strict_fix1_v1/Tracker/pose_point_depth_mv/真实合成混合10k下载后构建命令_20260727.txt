#   pose_point_depth_mv/dataset_tools/
#   旧 ar_pose_trellis/pixal3d_multiview 路径仅保留兼容转发。

# 目标：
#   - 6000 个 Objaverse 对象
#   - 4000 个 OmniObject3D 扫描对象
#   - train/val/test = 9000/500/500 个对象，严格 object-disjoint
#   - 每对象最终冻结 1 条通过严格门的 8-view 序列
#
# 重要边界：
#   1. OmniObject3D 提供的是真实扫描 Mesh；本流程对它重新渲染，因此观测图仍是
#      合成相机观测，不应声称为真实世界 AR 视频。
#   2. 这里构建的是 SS/SLAT 上游所需的 object-centric 多视图基础数据。
#      因为 Mesh 会规范化到 canonical object frame，本阶段不使用 TM2W。
#   3. 最终冻结脚本不会复制 8 万张图；它创建指向分片产物的软链接。
#      因此 strict_render_v9gate_cyclescuda_v2 在最终数据使用期间必须保留。
#   4. 旧 v9 的对象通过率约为 1153/5000。代码不承诺一定凑够 10k：
#      任一来源的严格通过对象不足时会硬失败并显示缺口，不会复制对象凑数。
#   5. 分片构建阶段关闭“分片内动态低纹理配额”，最终冻结时在每个来源上统一执行
#      max_low_texture_ratio=0.22；这样结果不依赖分片数量和完成顺序。
#   6. 本节点的 EEVEE+Xvfb 会落到软件 OpenGL（约 222 秒/24-view
#      sequence），不可用于 10k。正式后端冻结为无显示 CYCLES+CUDA。
#      如果改成 CYCLES，必须在所有分片开始前统一修改；禁止混用。每个 manifest
#      已绑定完整 build_config，最终冻结会拒绝配置不同的分片。
#
# 本文件中的所有执行块都不使用 set -e，也不调用 exit；失败后当前终端仍保留。
