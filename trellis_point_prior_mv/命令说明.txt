目录：
/home/zjr/Tracker/trellis_point_prior_mv

目标：
这是 Points-to-3D + 多视图 pose 思路的第一阶段原型。它不改 ar_pose_trellis / pixal3d_multiview / ReconViaGen 原代码。

核心流程：
1. 使用现有 Pixal V9 多视图合成数据和已预计算 TRELLIS sparse latent。
2. 从完整 target_coords 抽取 64^3 occupancy 的表面 voxels。
3. 用多视图 pose + mask 筛出被多视角支持的 object surface voxels。
   当前默认启用 front-depth z-buffer，只保留每个 view 每个像素附近最前面的 surface voxel。
   当前默认禁止 support fallback；如果投影/坐标系/mask support 失败，prior 会为空并在 report 中标记 support_failed。
4. 退化成 AR-SLAM-like sparse point prior：
   - 1/2/4/8 个视角；
   - 50/100/300/800/1500 点；
   - dropout；
   - voxel jitter；
   - 少量 random outlier。
5. 训练 TRELLIS sparse structure flow 的 LoRA + SparsePointPriorCond。
6. 测试 correct / empty / shuffle / random / jitter prior 的 fixed-topk sparse IoU/recall/rank。

当前不是最终完整 Points-to-3D：
这里先把 partial latent/mask/confidence 映射成 flow condition tokens，不直接改 flow 的 x_t inpainting clamp。
如果这一版能在 fixed-topk eval 中体现 correct prior 排名优势，再做第二阶段 visible latent clamp / boundary refinement。

1. 把 observed latent 直接 clamp 到 x_t / x0 采样路径；

十、当前修正后的重要诊断字段

build_report.json / build_report.csv 里重点看：

support_failed：
1 表示该样本通过 pose+mask+front-depth 没筛出任何 supported surface。默认不会 fallback，这类样本 prior_point_count 会是 0。

fallback_used：
默认应为 0。只有显式设置 ALLOW_SUPPORT_FALLBACK=1 或 --allow_support_fallback 才可能为 1。

supported_surface_count：
这是 fallback 前的真实 supported surface 数，不再是 fallback 后的 sampling pool 数。

sampling_pool_count：
实际用于采样 prior 的 surface pool。默认等于 supported_surface_count；只有打开 fallback 时才可能不同。

eval 公平性：
同一个 sample 的 correct/empty/shuffle/random/jitter 现在使用同一份 sparse sampler 初始 noise，差异来自 prior condition，不再来自随机 noise。

confidence：
prior_conf 会写入 npz、进入训练和评测 condition。random outlier 的低 confidence 不会被重置成 1。

十一、Stage 2：Points-to-3D 式 sparse structure inpainting 原型

背景：
前面的 oracle smoke 已经说明，单纯把 point prior encode 成普通 condition token 不够。即使 prior 是 8 视角、1500 点、无 dropout、无 outlier，correct 也不能稳定胜过 shuffle/jitter。

Stage 2 的代码不覆盖 Stage 1，新增入口：

训练：
/home/zjr/Tracker/trellis_point_prior_mv/train_sparse_inpaint_stage2.py

评测：
/home/zjr/Tracker/trellis_point_prior_mv/eval_sparse_inpaint_stage2.py

一键脚本：
/home/zjr/Tracker/trellis_point_prior_mv/scripts/run_pixal_v9_point_prior_stage2.sh

Stage 2 做了什么：
1. 仍然使用 build_point_prior_dataset.py 构建 prior。
2. 将 prior voxelize 后编码成 partial latent / known latent mask / confidence。
3. 训练时构造 mixed inpainting target：
   - known 区域 target = known partial latent；
   - unknown 区域 target = full target sparse latent。
   关键点：known 区域不再用 full target_x0。
4. 训练时 x_t 由 mixed target 加噪得到，因此 known latent 真的进入 x_t。
5. 训练时在 known latent 区域增加 flow / predicted x0 一致性权重。
6. 评测采样时做 timestep-correct known latent clamp：
   - 每个 denoising step 后，用同一份 known noise 将 known latent 加噪到当前 t_prev；
   - 再把该 noised known latent 注回 sample。
7. 评测 final logits 可选支持 known point reinjection：
   - 对输入 point prior 对应的 64^3 logits 加 boost，使 known points 不再被 top-k 完全丢掉。
   严格 inpainting 主实验默认关闭这个功能。
8. eval/report.json 会额外统计：
   - prior_recall：生成 sparse 覆盖输入 prior 点的比例；
   - prior_precision：生成 sparse 中有多少比例落在输入 prior 点上。

重要参数：

KNOWN_FLOW_LOSS_WEIGHT：
known latent 区域 flow MSE 的额外权重，默认 2.0。

KNOWN_X0_LOSS_WEIGHT：
known latent 区域 predicted x0 一致性 loss 权重，默认 1.0。

KNOWN_USE_CONFIDENCE：
是否把 confidence 用到 inpainting target / timestep clamp 的 known 区域权重里，默认 0。
默认 0 时：
- condition 仍使用 confidence；
- inpainting target 的 known 区域只由 latent_mask 决定；
- known target = raw known partial latent，不再被 confidence 缩小。
设置为 1 时：
- known_weight = latent_mask * confidence；
- 更适合真实 AR/SLAM prior 中点云噪声较高的情况。
第一轮 strict oracle 必须保持 0，否则 oracle 点云会被 density confidence 软化。

KNOWN_LATENT_CLAMP_STRENGTH：
采样阶段每步 latent reinjection 强度，默认 1.0。
0 表示不做 latent clamp，只保留训练侧 known loss。
1 表示 known latent 区域强制替换为 partial latent。

KNOWN_LOGIT_BOOST：
最终 decoder logits 上对 prior coords 的 boost，默认 0.0。
0 表示不做 final logits reinjection。

CLAMP_INITIAL_NOISE：
是否在初始 noise 阶段也注入 noised known latent。默认 1。

十六、Stage 2 结果判断标准

第一层：known point 是否真的进入输出。
看 summary.correct.prior_recall_mean。
如果 prior_recall 仍然很低，说明 known latent/logit reinjection 没接好。

第二层：correct 是否压过 random/empty。
如果不能压过 random/empty，说明点云本身没有被有效使用。

第三层：correct 是否压过 shuffle/jitter。
这是最关键的样本级几何绑定指标。
如果 correct 仍然输给 shuffle/jitter，说明当前只是在做点云覆盖或物体先验增强，没有学到“当前点云对应当前物体”的补全。

第四层：latent-only 和 logit-only 的差别。
如果只有 logit-only 有提升，说明它更像后处理点插入。
如果 latent-only 也有提升，说明 flow 采样路径开始受 known structure 约束。

第五层：是否进入 wrong-prior ranking。
如果 Stage 2 oracle smoke 能让 correct 明显优于 empty/random，但仍压不住 shuffle/jitter，下一步才加 wrong-prior ranking：
1. 同一个 target；
2. 同一个 t/noise；
3. correct prior loss 应低于 shuffle/random prior；
4. ranking loss 同时看 known consistency 和 unknown completion。

十八、Stage 2 补 known / unknown 分区指标

本轮已在：

trellis_point_prior_mv/eval_sparse_inpaint_stage2.py

中新增分区指标。定义方式如下：

1. known region：
   prior sparse points 映射到 16^3 TRELLIS sparse latent cell 后，这些 cell 覆盖到的 64^3 target/pred 坐标。
   这和 Stage 2 当前 hard latent clamp 的真实作用区域一致。

2. unknown region：
   target/pred 中不落在 known latent cell 的部分。

3. exact_unknown：
   直接按 64^3 exact prior point 做 target - prior / pred - prior 的补充诊断。
   这个指标比 known/unknown 更严格，但不完全等价于 latent clamp 作用区域。

新增重点字段：

- known_iou
- known_target_recall
- unknown_iou
- unknown_target_recall
- exact_unknown_iou
- exact_unknown_target_recall
- known_prior_recall
- prior_target_overlap_ratio
- wrong_prior_leak_rate
- wrong_prior_leak_pred_fraction
- summary.correct_rank_unknown_iou
- summary.correct_rank_unknown_target_recall
- summary.paired_delta

十九、Stage 2 公平 observed split 指标

上一节的 `unknown_*` 是 condition split：

- correct mode 用 correct prior 切 known/unknown；
- shuffle mode 用 shuffle prior 切 known/unknown；
- random mode 用 random prior 切 known/unknown；
- jitter mode 用 jitter prior 切 known/unknown。

这适合分析“当前输入 prior 自己造成了什么影响”，但不适合直接比较：

- correct.unknown_iou vs shuffle.unknown_iou；
- correct_rank_unknown_iou；
- paired_delta 的 unknown_iou。

因此已新增一套公平 common observed split：

- `obs_known_*`：所有 mode 都使用 correct prior 映射到 16^3 latent cell 后覆盖的 64^3 区域；

这样 `obs_unknown_iou` / `obs_unknown_target_recall` 可以直接比较 correct、shuffle、random、jitter。

二十一、Stage2 mesh frozen downstream 相对 top-k / cap sweep

目的：

前面固定 `4096 / 8192 / 12000 / target_unique` 的想法只适合单样本。多样本时各样本 `target_unique` 差异很大，固定 top-k 会把“小物体过满”和“大物体欠采样”混在一起。因此新增相对 top-k 规格：

- `target_unique`：使用该样本 GT sparse 数量，只作为 oracle 上限；
- `r0.50_cap8192`：`round(0.50 * target_unique)`，但最多 8192；
- `r0.75_cap12000`：`round(0.75 * target_unique)`，但最多 12000；
- `r1.00_cap12000`：`target_unique`，但最多 12000；
- `abs8192` 或 `8192`：固定 8192，保留兼容。

脚本参数：

```text
--stage2_topk_specs r0.35_cap4096,r0.50_cap8192,r0.75_cap12000,r1.00_cap12000,target_unique
```

如果给了多个 spec，`stage2_correct` 会自动展开成多个 mode，例如：

```text
stage2_correct_r0_35_cap4096
stage2_correct_r0_50_cap8192
stage2_correct_r0_75_cap12000
stage2_correct_r1_00_cap12000
stage2_correct_target_unique
```

同一个样本只采样一次 Stage2 logits，再从同一份 logits 里取不同 top-k，避免不同随机噪声影响 sweep。

二十二、Stage2 anti-overfill 训练与测试

目的：

前面相对 top-k sweep 证明：降低 top-k 可以减少复杂度，但不能根治过满，说明 Stage2 logits 的空间分布本身偏扩张。因此本轮修改训练目标，而不是继续只调 top-k。

新增训练项：

```text
anti_overfill_loss = mean softplus(decoder(pred_x0) + margin) on voxels outside GT target sparse
```

含义：

- 用 frozen TRELLIS sparse decoder 把 Stage2 预测的 `pred_x0` 解成 occupancy logits；
- 在 GT target sparse 之外的位置惩罚正 occupancy；
- 目标是提高 precision、压制 overfill；
- 默认 `ANTI_OVERFILL_LOSS_WEIGHT=0.0`，旧实验不受影响。

新增采样参数：

```text
KNOWN_CLAMP_START_T
```

默认 `1.0`，等价旧行为。设为 `0.5` 时，只在后半程 diffusion reinjection known latent，用来测试早期 hard clamp 是否推高 overfill。

## 二十四、Hard-negative ranking smoke

当前 ranking 不是单一 `outside_correct < outside_wrong`。训练里同时包含：

```text
observed margin: correct condition 在 correct observed support 上应强于 wrong condition
wrong-support empty: wrong prior 落在 GT 外的 support 应被压为空
target-support occupied: correct prior 落在 GT 内的 support 应被拉实
```

## 三十八、输入帧选择、RGB->SLAM pose 构建与 wrapper 默认策略修正

时间：`2026-06-23 06:12:15 UTC`

### 1. 数据构建注意事项

对于图像帧较多的真实/大型数据集，不应该把所有帧都输入 TRELLIS/Stage2/mesh eval。原因：

```text
1. 帧数太多会显著增加条件编码和评估耗时；
2. 连续相邻帧高度重复，不能有效增加物体覆盖；
3. 简单平均抽帧可能刚好落在轨迹重复/遮挡/模糊段；
4. 真实 AR 采集本质上也不是全帧输入，而是 keyframe / tracking map 输入。
```

现在支持的帧选择：

```text
first                 取前 N 帧，只适合 debug
uniform               均匀抽帧，确定性强，但随机性不足
random                全局随机，可能覆盖不均
random_uniform        按时间分 bin，每个 bin 随机取一帧；适合无 pose 前的 RGB->SLAM
pose_farthest         基于相机中心 farthest point sampling；适合已有 pose 后
pose_random_farthest  farthest + 随机性；当前内部真实数据默认推荐
stride                固定步长，适合已知帧率/轨迹稳定的视频
```

推荐：

```text
RGB video -> 离线 COLMAP/SLAM 估计 pose:
  COLMAP_FRAME_SELECT=random_uniform

已有 pose 后构建 Stage2 输入:
  FRAME_SELECT=pose_random_farthest
```

构建数据集还需要注意：

```text
1. 每个样本至少保留 8-16 个有效 keyframes；
2. 相机视角尽量覆盖目标物体 180-360 度，而不是集中在一个正面；
3. 保留一定随机性，避免模型只适配固定轨迹；
4. mask 要和 RGB 同尺寸同命名，边界过松会引入背景点，过紧会丢掉物体边缘；
5. pose 和 point 坐标系必须一致；
6. prior_bbox normalization 对局部点云敏感，要记录 normalization_scale；
7. 每个样本都要记录 point_count / support / mask-hit / extent，用于后续拒绝坏 prior；
8. 训练集应混合 strong/weak prior、strict/relaxed prior、不同点数和不同覆盖度；
9. 评估集不能只看成功样本，要保留低纹理、遮挡、mask 质量差、点数少的失败样本；
10. reference mesh 只用于 target/eval，不能参与 prior 构建。
```

## 三十九、RGB->COLMAP prior 的 direct / streaming 两分支对照

时间：2026-06-23 UTC

### 1. 为什么要加 direct COLMAP points 对照

上一版 `RUN_RECONSTRUCT_POSE=1` 默认路线是：

```text
RGB -> COLMAP pose+points
    -> 用 COLMAP pose 固定相机
    -> triangulate_slam_like_points.py 重新做 sequential pair triangulation
    -> mask/pose filter 后得到 object prior
```

这条更接近未来 AR/SLAM streaming object points，但它不是最直接的 RGB->SLAM prior。
现在新增显式分支：

```text
PRIOR_BRANCH=colmap_direct
```

含义：

```text
RGB -> COLMAP pose+points
    -> 直接使用 COLMAP points3D.txt
    -> build 阶段投影到 mask，筛出 object prior
```

另一个分支：

```text
PRIOR_BRANCH=streaming
```

含义：

```text
RGB -> COLMAP pose+points
    -> 使用 COLMAP pose
    -> 重新执行 streaming pair triangulation
    -> 得到更接近未来 AR-like 的 object prior
```

这两个分支回答的问题不同：

```text
colmap_direct:
  COLMAP 原生 sparse map points 经过 mask filter 是否已经够用？

streaming:
  固定 pose 下的 sequential/pair triangulation 是否比 COLMAP 原生点更适合 Stage2？
```

如果 `colmap_direct` 已经很好，第一版 proxy 可以简化；
如果 `streaming` 明显更好，说明当前 object-point filtering/triangulation 更适合后续 AR/SLAM 接入。

### 6. 当前新增 guard 和诊断字段

`run_ar_like_streaming_slam_eval.sh` 现在增加了几个硬 guard：

```text
1. PRIOR_BRANCH=colmap_direct 且 RUN_RECONSTRUCT_POSE=0 时：
   会提前检查每个 DATASET 的 ${SPARSE_SUBDIR}/points3D.txt 是否存在。

2. RUN_TRIANGULATE=1 时：
   如果 SPARSE_SUBDIR == TRI_INPUT_SPARSE_SUBDIR，会提前退出，避免覆盖输入 sparse。

3. RUN_RECONSTRUCT_POSE=1 时：
   shell 层先检查 COLMAP_BIN 是否存在，不再等 Python 深处报错。

4. COLMAP_OVERWRITE 控制是否覆盖 COLMAP 输出：
   COLMAP_OVERWRITE=1 适合 smoke；
   COLMAP_OVERWRITE=0 适合正式批量实验，避免误删已有 reconstruction。
```

COLMAP reconstruction report 现在额外记录：

```text
registered_image_count
registered_ratio
points3D_count
mean_reprojection_error
camera_count
sparse_model_count
intrinsics_source
camera_model
camera_params
fix_intrinsics
```

默认最低质量 guard：

```bash
COLMAP_MIN_REGISTERED_IMAGES=8
COLMAP_MIN_POINTS3D=100
```

如果想跑特别小的 smoke，可以显式调低：

```bash
COLMAP_MIN_REGISTERED_IMAGES=4 \
COLMAP_MIN_POINTS3D=20
```

`build_real_slam_prior_manifest.py` 现在也会优先从 `sparse_subdir/images.txt` 已注册图像中选帧，避免 `MAX_FRAMES/FRAME_SELECT` 从原始全量 images 中选到 COLMAP 没注册的帧。build report 新增：

```text
frame_image_mask_pair_count
frame_registered_image_count
frame_registered_pair_count
frame_unregistered_pair_count
frame_requested_count
frame_unmatched_count
frame_selection_source
frame_unmatched_names
frame_unregistered_names
```

如果 `frame_registered_pair_count` 很低，说明 COLMAP/SLAM 注册帧不足；如果 `projection_matched_frame_count` 明显低于 `frame_requested_count`，说明 sparse pose/image name/mask 仍有对不齐问题。
