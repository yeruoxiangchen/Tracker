# ReconVGGT AR Adapter A：zero-init token adapter / token layout sanity

## 1. 目的

本目录只实现 A 阶段：

```text
VGGT token adapter eval-only / zero-init sanity
```


也就是先确认：

```text
1. VGGT aggregated_tokens_list 的 shape / view 维 / token 维；
2. ReconViaGen 当前使用的 [4,11,17,23] 层 token layout；
3. 前 5 个 token 是否应按 prefix/global/register token 处理；
4. spatial token 数是否能还原为 per-view 2D token grid；
5. zero-init residual adapter 插入后，ss_cond / slat_cond 不变。
```

本阶段不训练 ReconViaGen 主干，也不替代 VGGT。它只保存一个 zero-init adapter checkpoint，并验证插入点安全。

默认行为：

```text
inspect_and_sanity.py 默认跳过 DreamSim 初始化。
```

原因是 A 阶段只需要：

```text
VGGT aggregator
sparse_structure_vggt_cond
可选 slat_vggt_cond
```

不需要 DreamSim。ReconViaGen `from_pretrained()` 会额外加载 DreamSim，而 DreamSim 内部可能触发 `torch.hub` 读取 `facebookresearch/dino` 缓存；如果本地缓存损坏，会出现：

```text
zipfile.BadZipFile: File is not a zip file
```

因此本脚本默认用 stub 跳过 DreamSim。只有你需要复现 ReconViaGen refine / perceptual loss 路径时，才加：

```text
--load_dreamsim
```

## 5. A 阶段“训练”说明

A 阶段不做真正训练；它只创建并保存 zero-init adapter：

```text
zero_init_adapter.ckpt
```

这是为了保证 adapter 插入点严格等价于原 ReconViaGen。只有 A 阶段通过后，B 阶段才考虑：

```text
AR pose + point-prior projection features
-> VGGT token gating / attention bias / geometry-aware residual
```

## 6. B 阶段前必须确认的 token layout 风险

重点看 `report.md` 的表格：

```text
layer shape:
  必须是 [B,V,T,C]，否则 view 维已经不可靠。

prefix:
  当前 ReconViaGen sparse_structure_vggt_cond 使用 patch_start_idx=5。
  本脚本默认 ss_image_cond_mode=skip_prefix，与 ReconViaGen run() 里的
  get_ss_cond(image_cond[:, :, 5:], ...) 对齐。

spatial tokens:
  T - 5 必须能开平方成 side x side。

pixel/token:
  518 / side 是 token 到图像尺度的粗映射。
```

如果 `T - 5` 不是平方数，或者不同层 token 数不一致：

```text
不要做 naive projection-to-token-grid；
先做 learned token gating / attention bias，而不是按像素坐标硬采样 VGGT token。
```

## 9. B2：adapter-only point-prior signal-injection smoke

B2 不是最终 mesh 训练。它只验证：

```text
point-prior projection token feature
是否能驱动 ProjectionAwareSpatialTokenAdapter
产生受控 spatial-token bias，
并且训练后的 ss/slat condition drift 可监控。
```

训练目标：

```text
hit token:
  directional score 接近 small target

miss token:
  directional score 接近 0

regularization:
  bias L2
```

注意：

```text
不能只用 energy/norm loss。
zero-init adapter 初始 bias 为 0，energy-only 目标在零点没有方向，可能没有有效梯度。
B2 当前使用 fixed random direction 的 directional score loss，因此可以从严格 zero-init 启动训练。
```

判断：

```text
score_hit_mean > score_miss_mean
energy_hit_mean > energy_miss_mean
energy_separation 明显 > 0
final ss/slat drift 不能异常大
```

## 10. B2 scale ablation：先找更温和的注入强度

当前 `bias_target_scale=0.02` 已证明可以学习 point-hit token signal：

```text
score_separation ~= 0.014
energy_separation ~= 0.00025
prefix diff = 0
```

但它也带来：

```text
ss_cond_max_abs_diff = 0.25
slat_cond_max_abs_diff = 0.03125
```

进入 B3 downstream 前，先跑更小注入强度：

```text
bias_target_scale = 0.005
bias_target_scale = 0.010
```

判断：


## 11. B2 drift 分布统计复跑

因此不能只看 max。当前 `run_b_projection_sanity.py` 已新增：

```text
selected_token_diff_stats:
  max / mean / p95 / p99 / rmse

ss_cond_diff_stats:
  max / mean / p95 / p99 / rmse
```

## 13. B3 mask-aware object-centric smoke

12.2-12.3 使用的是 full RGB，没有使用 `${DATASET}/masks`。这适合验证 adapter injection 是否传导，但最终目标是 object-centric mesh，因此下一轮需要 mask-aware B3。

重要：第一版只做 `mask apply, no crop`。

```text
原因：
当前 projection token feature 按原始相机内参 / 原图坐标投影到 37x37 token grid。
如果直接 mask+crop，图像 token 坐标系会变，但 projection feature 仍在原图坐标系，二者错位。
```

因此先用：

```text
--mask_mode apply
--mask_background black
```

它只把背景置黑，不裁剪，保持投影坐标系一致。

### 14.8 判断

```text
如果 stronger adapter 只改变 coord_count / mesh size，但 prior/projection 指标没有改善：
  当前 B2 adapter 只是扰动 VGGT token，不是有效 point-prior alignment。

如果 within_prior_radius_ratio 和 projection_keep_ratio 上升，同时 mesh 不变碎：
  可以进入 B4：把 B2 supervision 从 direction-score proxy 改成 downstream sparse/prior-alignment proxy。

如果 scale020 a1.0 明显破坏 component 或 visible_outside_mask_event_ratio：
  不跑它的 mesh，保留 scale010 a1.0 或 scale020 a0.5。

如果所有 masked adapter 与 masked no-adapter 差异仍很小：
  停止只做 token bias 的 eval-time injection，转训练期接入 VGGT/SLAT 条件或 crop-aware object-centric projection。
```

## 15. B4.0 delta-level prior alignment 诊断

本节新增脚本：

```text
reconvggt_ar_adapter_a/eval_b4_delta_prior_alignment.py
```

用途：

```text
比较 baseline coords 与 adapter coords：
  added = adapter - baseline
  removed = baseline - adapter
  kept = adapter ∩ baseline
  union = adapter ∪ baseline

分别统计 prior distance、within prior radius、projection/mask support、outside-mask event。
```

注意：

```text

```

## 16. B4.1 mask-aware gated adapter

### 16.0 结论与路线切换

第 15 节 delta 诊断结论：

```text
scale010 a0.5:
  delta 方向干净，但只改变 16 个 voxel，影响太小。

scale010 a1.0:
  added 的 mask support 低于 removed，outside-mask 明显变差。

scale020 a0.5:
  added 更靠近 prior，但 mask support 略低，outside-mask 变差。

scale020 a1.0:
  added 更靠近 prior、mask support 更高，但 outside-mask 仍变差。
```

因此停止旧路线：

```text
pose + unmasked COLMAP point projection -> token bias
```

不再继续旧 adapter 的 mesh / runtime-scale sweep。

进入 B4.1：

```text
pose
+ mask-filtered object point projection
+ token foreground mask
-> gated token bias
```

新增代码能力：

```text
1. build_token_mask_features:
   mask_dir -> per-token foreground ratio / foreground hit

2. build_colmap_point_projection_features / build_point_projection_features:
   支持 mask_dir，把 projected points 过滤到 object mask 内

3. ProjectionAwareSpatialTokenAdapter:
   支持 gate_feature_index，把 bias 限制在 token mask 支持区域

4. train_b_projection_adapter.py / run_b3_adapter_injection_smoke.py:
   支持 --mask_projection_mode filter_points_token_mask
   支持 --adapter_gate_feature_index -1
```

## 18. B4.2 多视图一致 object point support

### 18.0 本节代码改动

新增参数：

```text
--point_mask_support_min_views
--point_mask_support_min_ratio
```

改动文件：

```text
reconvggt_ar_adapter_a/projection_token_features.py
  build_point_projection_features()
  build_colmap_point_projection_features()
  新增 point-level multiview mask support 过滤和 summary。

reconvggt_ar_adapter_a/train_b_projection_adapter.py
  build_projection_features() 接入 point support 参数。
  CLI 新增 point support 参数。

reconvggt_ar_adapter_a/run_b3_adapter_injection_smoke.py
  CLI 新增 point support 参数，保证训练和 sparse eval 使用同一 feature 构造。
```

含义：

```text
旧 B4.1:
  每个 view 内先投影点，再按该 view mask / token mask gate。

新 B4.2:
  先把每个 3D point 投影到所有 selected views；
  统计该 3D point 在多少 view 内落入 object mask；
  只保留满足多视图 mask support 的 object-supported 3D points；
  再进入原 token projection / token gate。
```


cache builder 对每个样本执行硬检查，不再跳过非法样本或 clip 越界坐标。每个 split 同时生成
`cache_audit.json`，记录 14 个 channel 的 min/max/mean/nonzero ratio、view 分布、prior/mask support
